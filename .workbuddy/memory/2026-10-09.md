# 2026-10-09

## 桌面端媒体库入口迁入左侧 Rail（取消顶部 TabBar）

需求：桌面端（Windows/Linux/macOS）媒体库去掉顶部 6 个 Tab，入口全部放进左侧 Rail；
窗口高度装不下时 Rail 可滚动，设置页固定左下角。

讨论后确定的三个决策：
- Rail 宽度：桌面宽窗口（>=900px）展开为 216px 图标+文字，窄窗口收回 80px 纯图标
- 媒体库子入口：折叠式，只在媒体库页（index 2）激活时展开
- 平台范围：挂在 `useSidebar` 开关上（含 iPad 横屏），不再按 Platform 分叉

改动：
- `lib/utils/layout_constants.dart`：新增 `kSidebarRailWidthCollapsed=80`、
  `kSidebarRailWidthExtended=216`、`kSidebarRailExtendedMinWindowWidth=900`、
  `sidebarRailWidthFor(width)`，作为 rail 宽度唯一来源，替换散落的硬编码 `80.0`
- `lib/pages/main_layout.dart`：`_SlidingNavigationRail` 从 StatelessWidget 改为
  StatefulWidget（带 ScrollController）；条目改为「可滚动区 + 常驻底部设置」两段结构；
  胶囊指示器 Y 偏移改为按行累加（`_RailRow` + `offsetOf`），不再用
  `activeIndex * itemHeight`；新增 `isLibraryExpanded` / `librarySubIndex` /
  `onLibrarySubDestinationSelected` 参数
- `lib/pages/library_page.dart`：删除 TabController 与 `_buildLandscapeLayout`，
  新增 `_buildSidebarLayout`（`IndexedStack` + `libraryActiveTabIndexProvider` 驱动，
  `_builtSubTabs` 按需实例化）；topPadding 从 `safeTop+56` 降到 `safeTop+8`，
  纵向多出约 48px；新增 `railWidth` 入参

踩到的坑：
- Riverpod 读 notifier 必须写 `ref.read(xxxProvider.notifier)`，写成
  `ref.read(xxxProvider).notifier` 会报 undefined_getter
- LibraryPage 的 initState 会用 `initialTabIndex` 回写 provider，若用户先在别的页面
  通过 Rail 选了子页，会被覆盖回第一个子页 → 改为 provider 已有值时优先用 provider
- 本机 `flutter` 不在 PATH，需要 `export PATH="$HOME/flutter/bin:$PATH"`；
  sandbox 会拦 `~/.pub-cache` 写操作，必须用 `flutter analyze --no-pub`
- Android 打包时又在 main_layout.dart:1313/1319 暴露了同一个 `.notifier` 位置错误
  （Rail 子入口回调里漏网的两处），已改为括号内 `.notifier`；analyze 确认 lib/ 零 error
