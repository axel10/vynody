## 修复：安卓上标准进度条拖动时拇指不跟手

**根因**：`PlaybackProgressSection.buildStandardSlider` 里 `Slider(value: displayProgress, onChanged: onScrubbing)`。Flutter `Slider` 是受控组件，鼠标/手指拖动时拇指位置完全取自传入的 `value`（`_RenderSlider.value ← widget.value`，内部 `_currentDragValue` 只用来算 onChanged 增量，不参与绘制）。而 `onScrubbing` 在 `playback_page` 里只写 `_scrubProgressNotifier`（供时间文本预览），没有回流到 `value`，于是拖动期间拇指停在按下位置，仅随引擎 250ms 上报的进度闪跳。波形进度条无此问题，因为它在内部持有拖动值。

**改动**（`lib/widgets/playback/playback_progress_section.dart`）：
- 新增私有 `_StandardProgressSlider`（StatefulWidget）：持 `_dragValue` + `_isDragging`，拖动期间 `didUpdateWidget` 直接忽略外部 `widget.value`，只用自己的值绘制；松手 `onChangeEnd` 调 `onSeek`，之后由外部进度接管（追平容差 `_handoffEpsilon = 0.005` 或 >0.2 大跳变即释放，另有 600ms Timer 兜底）。
- 不采用「把 notifier 的值传回 overrideProgress」的方案：会让 `playback_page` 每帧整页重建（封面/歌词/可视化）。

**同类检查**：`remote_control_page.dart` 的进度滑块已有 `_draggingSliderValue` + setState，模式正确；`MiniPlayerProgressInfo` 自绘且已有 `_dragValue`。

## 新增：远程媒体库下载「加载曲目」进度（共 N 首 / 已加载 M 首）

**背景**：点下载后曲目要么在服务端逐张专辑拉取（艺术家），要么逐首算落盘路径入队，期间只有一句 toast 或干脆静默，大批量时看不出卡在哪、还剩多少。

**结构**：
- `lib/player/remote/services/remote_track_load_progress.dart`：单例 `remoteTrackLoadProgress`（`ChangeNotifier`），两阶段 `RemoteTrackLoadStage.loading / queueing`，字段 `loaded/total/fraction`。`isActive == false` 时所有上报被忽略 —— 播放、加入队列也走同一批 fetch 函数，靠这个开关避免误触发。
- `lib/dialogs/remote_track_load_progress_dialog.dart`：`runWithRemoteTrackLoadProgress(context, task)` 负责 `begin()/end()`；**220ms 后才弹**，避免小批量入队闪一下；阶段切换时清计数（两段口径不同）；`total == 0` 时不显示「0 首」，只留不确定进度条。
- 上报点：`fetchSubsonicArtistTracks` 用专辑列表的 `songCount` 求和当分母、每拉完一张专辑 `setLoaded(allSongs.length)`；`enqueue{Subsonic,Jellyfin,WebDav,Smb}Tracks` 入队前 `setStage(queueing)` + `setTotal`，每首 `advance()`。
- 包装点：专辑/艺术家/歌单右键下载、勾选批量下载（替换原 `_withLoading`）、歌曲页「全部下载」、艺术家/专辑/歌单详情页下载按钮。

**注意**：单张专辑/歌单是一次请求，拉取阶段没有中间刻度（总数只有响应里才有），所以那种场景只显示不确定进度条 —— 想要刻度就得从列表项把 `songCount` 一路传进 context menu，暂未做。


## 修复：多选多张专辑下载时进度浮层没有数字、一闪而过

**现象**：多选多张专辑 → 下载，浮层只显示「正在加载曲目」，没有「共 N 首 / 已加载 M 首」，而且弹出来瞬间就消失，直接跳到入队完成。

**根因**（两条叠在一起）：
1. 多选走 `RemoteLibrarySelectionActions.fetchSelectedSongs` 的**专辑分支**，这个分支逐张调 `fetchSubsonicAlbumTracks`，但**从没往进度源报数**（无 `setTotal`、无 `advance`）→ `total == 0`，浮层只剩不确定进度条 + 标题；而副文案被 `hasTotal || loaded > 0` 挡住，所以连「已加载 0 首」都不显示。
2. 每张专辑只有一次 `getAlbum` 请求，本地服务器几张专辑两三百毫秒就完事，旧阈值 220ms 才弹、task 一结束立刻 pop → 露一下就没了。

**改动**：
- `remote_track_load_progress.dart` 新增 `addToTotal(delta)`。多选多个艺术家时每个艺术家要先拿专辑列表才知道自己多少首，覆盖式 `setTotal` 会让分母只剩最后一个人的量，必须累加。
- `fetchSelectedSongs` 新增 `albumSongCounts` 参数：先按选中专辑的 `songCount` 求和一次性 `addToTotal`，每拉完一张 `advance(tracks.length)`。调用方 `remote_library_page._fetchSelectedSongs` 用 `_albums` 建 `albumId → songCount` map 传入。歌单分支拿不到分母，也补了 `advance`（至少「已加载 N 首」会走）。
- `fetchSubsonicArtistTracks` 改成 `baseLoaded + allSongs.length` 叠加上报（原来 `setLoaded(allSongs.length)` 多选时会把前一个艺术家已加载的抹掉）。
- 浮层：延迟 220ms → 120ms；新增 `_kProgressMinVisible = 420ms`，露过面就至少停这么久；新增 `immediate: true` 参数，批量下载（多选、全部下载、三个详情页的下载全部）立即弹出，不再靠延迟阈值赌。收起改用浮层自己的 `context`（`showDialog` builder 里回传），页面中途销毁也能关，不再挂在 rootNavigator 上。

**教训**：进度上报要跟着**分支**走，不是跟着函数名走 —— `fetchSubsonicArtistTracks` 加了上报、`fetchSelectedSongs` 里调它的兄弟分支（专辑）却漏了，结果最常见的入口反而没数字。
