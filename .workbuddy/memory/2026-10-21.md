# 2026-10-21

## Subsonic/Navidrome 关闭下载的适配（对应上游 PR #50）

**问题**：Navidrome `EnableDownloads=false` 时，`download.view` 仍回 HTTP 200，只是响应体换成
`{"subsonic-response":{"status":"failed","error":{"code":50,"message":"downloads are disabled"}}}`。
`_dio.download` 看到 200 即成功，错误体被当音频搬进音乐库并标记 completed（约 200 字节的"坏歌"）。

**决策**：明确失败 + Toast 提示，**不**静默回落到 `stream`（尊重服务端管理策略；PR #50 的做法是回落，未采用）。

**改动**：
- `subsonic_client.dart`：`errorDownloadsDisabled = 50`、`SubsonicException.isDownloadsDisabled`、
  `parseErrorBody()` / `parseErrorFile()`（后者只读 ≤64KB、非法 UTF-8 视为二进制）。
- `remote_download_service.dart`：`_dio.download` 之后、落盘判定之前嗅探错误体并抛出；
  catch 里 code 50 → 任务 error 用 l10n 文案 + 每个 server 只弹一次 Toast（`_downloadsDisabledServers`，
  成功下载后移除该 server 的标记）。临时文件由既有 `finally` 清理，故错误体不会落盘。
- `remote_media_resolver.dart`：转码 / AI 歌词走临时下载，同样嗅探并清掉 `transcode_temp/<id>` 目录再抛。
- l10n：`remoteServerDownloadsDisabled`，9 个 arb 同步 + `flutter gen-l10n`。
- 新增 `test/player/remote/subsonic_downloads_disabled_test.dart`（11 例，loopback 假 Navidrome）。

**环境注意**：本机 `HTTP_PROXY/HTTPS_PROXY` 指向 127.0.0.1:61086 时，`flutter test` 会以
"Unable to connect to flutter_tester process: Invalid WebSocket upgrade request" 全量失败。
跑测试前先 `unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy ALL_PROXY GLOBAL_AGENT_HTTP_PROXY`。

## 续：反向代理返回 HTML 错误页的适配

动机：#50 只处理了 Subsonic 的失败 JSON；若反向代理自己回 200 + HTML（nginx/CF 的 50x 页、
目录列表、登录门户），或上游回了 200 但内容不是音频，旧逻辑照样把网页搬进音乐库并标「已完成」。

- 新增 `lib/player/remote/services/remote_payload_guard.dart`：`RemotePayloadGuard.inspect(file,
  contentType, parseSubsonicError)`。只读文件头 2048 字节；先认音频魔数（ID3/fLaC/OggS/RIFF/
  ftyp/wvpk/MAC/DSD/ASF/0xFF 帧同步）直接放行，再走 `SubsonicClient.parseErrorBody` 拿真实错误码，
  最后按 Content-Type（text/*、json、xml）或首字节 `<`/`{`/`[` 判定为非媒体。
  非媒体抛 `RemotePayloadException`（`extends SubsonicException`，code=`errorNonMediaPayload`=-1），
  复用既有失败分支。
- `subsonic_client.dart`：删掉 `parseErrorFile`（64KB 阈值会漏几 MB 的错误页），只保留 `parseErrorBody`。
- `remote_download_service.dart`：`_dio.download` 的返回值接住，用 `HttpHeaders.contentTypeHeader`
  取 Content-Type 交给 guard；`_downloadsDisabledServers` 换成 `_warnedServerIssues`
  （serverId → 问题种类集合，成功下载后整组清空），code 50 与非媒体各自只提示一次。
- `remote_media_resolver.dart`：同一处校验，失败仍先删 `transcode_temp/<id>`。
- l10n：`remoteDownloadNotAudioResponse`（9 个 arb + gen-l10n）。
- 测试扩到 19 例：新增「几 MB HTML 仍识别」「text/html 正文非标记」「真音频 + text/plain 不误判」
  「普通二进制不误判」「非 Subsonic 协议 JSON」「队列 HTML 不落盘」「resolver HTML 抛错并清目录」。
- 坑：`ContentType.contentTypeKey` 不存在，用 `HttpHeaders.contentTypeHeader`。

## 续：Jellyfin 侧「服务端拒绝下载」的实际情况

- Jellyfin 下载走 `_JellyfinDownloadSource.buildDownloadUrl` → `JellyfinClient.buildStreamUrl`
  （`/Audio/{id}/stream?static=true&api_key=`），**不是** `/Items/{id}/Download`。
  用户策略里的「允许下载」(EnableContentDownloading) 管的是后者，所以 Jellyfin 侧
  不存在 Subsonic code 50 那种「200 + 失败 JSON」，无需 fallback。
- Jellyfin 真正的拒绝方式是标准状态码：401（token 失效）/ 403（无权限）/ 404（曲目不可见或已删），
  Dio 抛 DioException，临时文件不会落盘（不会静默坏歌）。缺的只是文案。
- `remote_download_service.dart` 新增 `_describeHttpFailure(Object)`：401/403 →
  `remoteDownloadUnauthorized` + 每 server 提示一次（kind=`download_rejected`）；
  404 → `remoteDownloadTrackMissing`（只落到任务 error，不弹 Toast）。其余仍透出原始异常。
- l10n 新增 `remoteDownloadUnauthorized` / `remoteDownloadTrackMissing`（9 个 arb + gen-l10n）。
- 测试扩到 22 例（`_FakeNavidrome` 增加 `/Users/AuthenticateByName` 与 `downloadStatusCode`，
  `bootstrap` 增加 `serverType`）：Jellyfin 正常 / 403 / 404。
- **顺带发现的既有 bug（未修）**：`RemoteMediaResolver.downloadRemoteTrackToTempFile` 只判
  `type == subsonic`，其余全走 `WebDavClient`，于是 Jellyfin / SMB 曲目做转码或 AI 歌词时
  会用 WebDAV 的 URL 去下，必然失败。

## 续：Jellyfin 转码 / AI 歌词「实机正常」的真相

用户实机测过 Jellyfin 的转码与 AI 歌词都正常，质疑上面那条「走 WebDavClient 必失败」的判断。
验证结论：**用户没错，我之前也没错——两者不矛盾，是缓存接住了。**

- `downloadRemoteTrackToTempFile` 第 1 步查 `AudioStreamCacheManager`，cacheKey = `${serverId}:${trackId}`，
  与 `resolvePlayableSource` / 播放预取（`playback_queue_processor`，默认 `remotePrefetchCount = 2`）
  写入的 key 完全一致 → 播过的曲目必然命中，直接拷本地，压根不走网络。
- 未命中时（清缓存、系统清 tmp、曲目没播过就点 AI 歌词 / 转码、预取设为 0）才会走到
  `else → WebDavClient`，拼出 `http://host/<trackId>` → 404。
- 用 `test/player/remote/jellyfin_temp_download_test.dart` 把两条分支都钉住：假 Jellyfin 只认
  `/Users/AuthenticateByName` 与 `/Audio/{id}/stream`，其余 404。

修复：`downloadRemoteTrackToTempFile` 按协议分派，不再「只判 subsonic、其余全 WebDavClient」：
- jellyfin → `authenticate()` + `buildStreamUrl(trackId, maxBitRate: 0)`（static=true 取原文件，
  转码/AI 分析不该拿服务端转码副本）
- smb → `LocalStreamProxy.instance.buildSmbStreamUrl(share, relativePath)`
- 其余仍 WebDavClient

验证：`jellyfin_temp_download_test` 2 例、`test/player/remote/` + l10n 共 59 例全绿，`flutter analyze` 无 error/warning。
