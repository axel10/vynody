# 2026-10-23

## FFT 采集是否改为「始终采集」——调研与建议（未落码）

用户诉求：播放页音频可视化开关关掉后，迷你播放器仍要有频谱动画；仅在 app 进后台时停。

### 现状链路（已核对）
- `AudioService._updateEffectiveVisualizerState()`（`lib/player/audio/audio_service.dart:1766`）是唯一切换点：`_userVisualizerEnabled && !_isAppBackgrounded && !_isWindowMinimized` → `_player.visualizer.setEnabled()`。
- `_userVisualizerEnabled = isProUnlocked && settings.isVisualizerEnabled`（`audio_service.dart:327`）。开关默认值：桌面 true、移动 false（`settings_service_test.dart:578`）。
- 关闭 → `VisualizerController.setEnabled(false)`：`resetState()` + `visualizerOutputManager.stopAll()`（`audio_core/lib/src/visualizer_controller.dart:64`），`processAnalysisTick` 直接 return（:96）。所以迷你播放器的 `mini_player` 输出也跟着停——它的数据源 `_currentRawBins` 同由这条 analysis tick 更新，输出流自己的 60Hz 定时器喂不到数据。
- 播放页自身的可视化层由 `shouldDrawVisualizer = audioIsVisualizerEnabledProvider && !isTransitioning`（`lib/pages/playback_page.dart:1046`）单独门控，与采集已解耦。
- Rust 侧 `setFftCaptureEnabled` 是空实现（`rust_audio_engine.dart:218`）；真按需——`FftSource::compute_fft` 只在 `last_fft_request_time` 1500ms 窗口内算，窗口由 `get_latest_fft()` 的 `record_fft_request()` 续（`audio_core/rust/src/api/simple/fft.rs:88`、`controller.rs:2295`）。
- Android 侧 `setFftCaptureEnabled` → `FFTAudioProcessor.isPaused`，只是跳过 FFT 计算，音频通路照样 copy。事件推送由 FFT hop 驱动（44.1k 下 512/44100 ≈ 11.6ms ≈ 86 次/秒），而 Dart `analysisFrequencyHz` = 30 → **约 3× 过量推送，属既有浪费，建议另开一单**（`MyExoplayerPlugin.kt:253` 的 `fftConsumerRunnable` 把 frameDurationMs 下限设到 5ms）。

### 建议方案（推荐 A）
A. 只改 `_updateEffectiveVisualizerState()`：采集门去掉 `_userVisualizerEnabled`，改成 `!bg && !minimized`（或 `isProUnlocked && !bg && !minimized`）。不改 audio_core，不动采样率。副作用：`_syncTicks` 恒定走 render tick（60Hz）而非 250ms position tick，位置精度更好、CPU 略增；关开关不再 `resetState()`（重开时动画从当前帧续起）。
B. 按需采集（`_userVisualizerEnabled || miniFftStream.hasListener`）：省 CPU，但 `VisualizerOutputStream.hasListeners` 没有变更通知，要在 audio_core 加回调，~30 行。且迷你播放器在播放时几乎总在树上，收益接近为零。

### 待用户拍板
非 Pro 用户是否也应看到迷你播放器频谱。现状是「意外被 Pro 门挡住」（非 Pro → `_userVisualizerEnabled` 恒 false → 迷你频谱不动）。选 A 若保留 `isProUnlocked` 项则维持现状，去掉则变成免费装饰。

## 落地：方案 A（已改完）

用户拍板：保留 Pro 门（非 Pro 依旧没有频谱），只把「采集」与「播放页显示」解耦。

改动两处：

1. `lib/player/audio/audio_service.dart`
   - 新增 `_isProUnlocked` 缓存字段，在初始化、`ref.listen(isProUnlockedProvider)`、设置监听、`setVisualizerEnabled` 四处同步，避免在 tick / lifecycle 热路径上 `ref.read`（ref 销毁后会抛错）。
   - `_updateEffectiveVisualizerState()` 改为 `_player.visualizer.setEnabled(_isFftCaptureAllowed)`，`_isFftCaptureAllowed = _isProUnlocked && !_isAppBackgrounded && !_isWindowMinimized`。
   - `_userVisualizerEnabled` 语义收窄为「播放页要不要画频谱」，只经 `isVisualizerEnabled` → `audioSnapshot` → `audioIsVisualizerEnabledProvider` 喂 `playback_page.dart` 的 `shouldDrawVisualizer`。

2. `audio_core/android/.../MyExoplayerPlugin.kt` 的 `fftConsumerRunnable`
   - `frameDurationMs` 由 `512/sampleRate` 计算（≈11ms）改为常量 `fftEmitIntervalMs = 33L`，对齐 Dart `analysisFrequencyHz = 30`。
   - 顺带修掉一个会让频谱滞后的隐患：原来每轮只 `poll()` 一帧，hop ≈86Hz 时队列会堆到 20 条上限，等于滞后 200ms+；现改为每轮 drain 全队列、按 playerId 只留最新一帧再发。
   - 队列空时消费者仍会停、由生产者重新 post，低帧率音源不会被 33ms 拖慢。

验证：`dart analyze lib/player/audio/audio_service.dart` 只余一处既有的 `currentPhase` 未使用警告；`flutter test test/player/audio`（24 个）与 `test/widgets/floating_dock_bottom_bar_test.dart`（12 个）全过。Android 侧未跑 gradle 编译，只做人工复核。

已知副作用（可接受）：Pro 用户播放中恒走 60Hz render tick（`_syncTicks` 不再切 250ms position tick），位置更平滑、CPU 略增；关开关不再 `resetState()`，重开时动画从当前帧续起。
