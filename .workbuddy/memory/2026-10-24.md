## 右键菜单 / 多选 一致性审计（未改代码）

起因：讨论「能多选的列表右键菜单都加个 multi_select」。

结论：`showSongContextMenu` / `showSongBottomSheet` 无 `onMultiSelect` 参数，所以 9 个具备多选能力的曲目列表全部缺右键入口：
queue_page:450、right_queue_panel:192、playlist_tab:518、album_detail_page、album_sections:362、
library_insight_list:833、folder_detail_view / folder_root_view、album_cover_flow_quick_detail_dialog:329、
remote_folder_browser_page:546。

不加的三处：library_dashboard_view（代码注明无选择 UI）、playback_track_info（复制语义）、
mini_queue_view（长按:281 直接弹菜单，本身没有多选能力）。

集中化可行性盘点：
- 弹出层已统一：`AppContextMenu.show` / `showModalSheet`，29 处 10 文件；裸 showMenu 仅 standalone_queue_app 3 处 + right_queue_panel:1147（排序用）。
- 样式层统一，但有两套 API 并存：A 组 `ContextMenuAction` + `buildContextMenuPopupItems`（album/artist/genre/year），
  B 组逐项 `buildContextMenuItem`（song 20 / remote 56 / lyrics_panel 17 / folder_bottom_sheet 10 / playback_track_info 9 / playlist_tab 4 = 117 处）。
  `buildContextMenuItem`（song_context_menu_utils:1218）只是 `AppContextMenu.buildItem` 的纯转发。
- 四个实体菜单同构率 81%：345 行里对比差异仅 65 行（artist vs genre），差异只涉及图标 / 封面 widget / 副标题 / 文案。
  每个文件都完整重复「签名 → groups → popup → sheet → finally 恢复 scope → switch 分发」六段。
- 多选状态：`librarySelectionStateProvider` 主用（13 处 mixin）。`SelectionStateMixin` 与 `SongSelectionMixin`
  逐行重复，后者仅 K=String 特化。`IndexSelectionController`（selection_utils.dart:117-244）**零引用死代码**。
  仍有 4 处裸 `_isSelectionMode` 本地实现：folder_page:39、remote_folder_browser_page:83、
  right_queue_panel:53、album_cover_flow_quick_detail_dialog:67（都在 overlay / 弹窗场景，改成全局 provider 会串扰）。

体量：album/artist/genre/year 共 1456 行；song_context_menu_utils 1235 行；remote_context_menu_utils 2288 行。

## 已落地：第 2 层，实体菜单声明化
