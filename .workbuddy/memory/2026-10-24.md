## 已落地：右键菜单的「多选」入口补齐

判定标准是「这个列表本身能进多选」，不是「菜单里缺不缺项」。入口统一走各菜单函数的可选
`onMultiSelect`（默认 null = 不显示），不动 `handleSongAction` / `handle*MenuSelection` 的签名：
选中 `multi_select` 后在各 `show*` 里提前 return。

### API

- `showSongContextMenu` / `showSongBottomSheet` + `VoidCallback? onMultiSelect`。**只在
  `SongContextMenuMode.full` 显示**——`title` / `artistAlbum` 是复制文案语境，没有选择态。
  弹窗里独立成组（多一条分割线），面板里追加在末尾。
- `showRemoteAlbumContextMenu` / `Artist` / `Playlist` / `Song` + `VoidCallback? onMultiSelect`，
  各自在 groups 末尾追加一个空组守卫的 `multi_select` 组（`buildContextMenuPopupItems` 会跳过空组，
  所以 `onMultiSelect == null` 时不产生多余分割线）。

### 接线的 26 处

本地 13：`playlist_tab`×2、`folder_detail_view`×2、`queue_page`×2、`right_queue_panel`（队列区）、
`library_insight_list`、`album_sections`、`album_detail_page`、`album_cover_flow_quick_detail_dialog`×2、
`remote_folder_browser_page`（WebDAV/SMB 歌曲行）。

远程 13：四个库 Tab（songs×2 / albums / artists×2 / playlists×2）、`remote_library_search_tab`（歌曲）、
`remote_album_detail_page`×2、`remote_artist_detail_page`、`remote_playlist_detail_page`×2。

语义一律照抄该页长按：四个库 Tab 是 `onUpdateAnchor(i); onToggleSelection(key)`；详情页
`enterSongSelectionMode(path)`；队列页 `lastAnchorIndex = index; enterSelectionMode(index)`；
`right_queue_panel` / `cover_flow` 是本地状态（前者 `_selectedIndices`，后者 `_isSelectionMode`）。
`folder_detail_view` 顺手把长按体抽成 `_enterSongSelection(file, matchedSongs)`，两处共用。

多选态下 `onMultiSelect` 一律传 `null`：这些页面的 more 按钮路径**没有** `isSelectionMode` 守卫，
若照旧显示，点一下会把光标下那首「取消选中」。

## 目录页缩放档位视图代码评审（只评不改）

评审对象：`c294fb54` / `129a14a5` / `6a7d2f15` 三个提交 + 工作区未提交的 `FolderZoomPolicy` 抽取。

**实锤 bug**：`folder_detail_view.dart:270` 与 `remote_folder_browser_page.dart:1093` 定位当前播放时用
`screenWidth - 32` 当可用宽度，但页面外有 `ConstrainedBox(maxWidth: folderPageMaxWidth=1700)`，
sliver 实际拿到的是 `constraints.maxWidth`。窗口宽于 1732 时每行偏移高估（1920 屏幕约 45px/行），
滚到错误位置。修法：把 LayoutBuilder 的 `constraints.maxWidth` 存进 State 字段供定位用。

**死代码（本系列制造）**：`FolderGridCard`（folder_grid_card.dart:374-587）、`SongGridCard`
（song_grid_card.dart:576-818）已零引用，约 457 行；`isFolderZoomLargeGrid` / `getFolderGridCrossAxisCount` /
`calculateFolderGridChildAspectRatio` / `isLargeGridTarget` / `isCompactListTarget` 五个符号零引用；
5 个 sliver 的 `viewMode` 参数全项目无人传（`_effectiveZoomScale` 回退分支恒不可达）；
settings 的 `folderViewMode` getter/setter 只剩写入，`_folderViewModeProperty` 无读者。

**结构问题**：`getFolderZoomGridCrossAxisCount` 与 `FolderZoomPolicy.calculateCrossAxisCount` 双入口；
`FolderZoomPolicy` 12 字段中 7 个（width/zoomScale/isPortrait/tier/textHeight/cardWidth/listTileExtent）无人读，
公有无参构造只为测试手搓；`SliverAnimatedZoomGridLayout` / `resolve` / `targetChildAspectRatio` 三份几何公式；
`FolderZoomItem`/`SongZoomItem` 用屏幕宽 `isWide(>=780)` 定字号而非 `cardWidth`；`RemoteServersSliver` 仍
`isGrid` 硬切 + 固定 delegate，没进统一 morph；头部偏移 48/190/200 魔法数两页各抄一份，Policy 没覆盖。

结论：Policy 解耦的是「公式」，没解耦「宽度来源」，因此重复从 4 份变 1 份，但偏移与真实渲染仍可能不一致。
