## 品牌图标改版：青底白标 → 白底墨标（方案 F）

### 起因与实测

用户怀疑 `assets/images/icon.png`（#39C5BB 底 + 白标）对比度太低不醒目。实测确认，并发现比对比度更严重的问题：

| 项 | 原值 | 判断 |
|---|---|---|
| 白标 / 青底 | 2.13:1 | 低于 WCAG 非文本 3:1 |
| 青底在浅色桌面 `#F2F2F2` | 1.90:1 | 浅色环境连轮廓都丢 |
| 青底在深色桌面 `#1E1E1E` | 7.84:1 | 深色环境正常 |
| 最细条纹间隙 @32px | ≈1.5px | 抗锯齿糊成白噪点，16px 读不出「V」 |

根因是**低对比 + 五元素细碎标记（3 条纹 + 长斜杆 + 椭圆头）叠加**，不是单纯配色。
参照：微信白标 on `#07C160` 也只有 2.38:1，但它是整块实心气泡，所以不受影响。

### 走过但否掉的方案

| 方案 | 标记/底板 | 否掉原因 |
|---|---|---|
| `#0B7A72` 深青底 + 白标 | 5.20 | 深色 Dock 里变成暗块，丢品牌资产 |
| `#39C5BB` + `#0E1B1A` 墨标 | 8.30 | 可接受，但浅色桌面轮廓问题没解 |
| 纯白 `#FFFFFF` + 墨标 | 17.64 | 浅桌 1.12:1 底板消失；深色 Dock 16.67 过亮刺眼 |
| 白 + 音符头 `#39C5BB` | — | 青色 2.00:1 发虚，且 24–32px 抢视觉重心（先看青点再看 V） |
| 白 + 音符头 `#12968D` | 3.42 | 备选，用户最终没选 |

**用户最终定：方案 F** —— `#F7F8F8` 底板 + `#0E1B1A` 标记 + 沿轮廓内缩 2px 叠 16% `#1B2321` 细边。

### 落地（已改仓库资产）

母版重做方式：**不再从旧 PNG 反推颜色**（旧 PNG 底板 R 通道有 45~152 的渐变色抖，反推会留脏色和灰盘），改为
1. `logo.svg` 的 path 按 `translate(x, y) scale(s)` 用 **Chrome headless** 渲成纯白标记蒙版（1024 / 1430）；
2. 底板轮廓仍沿用旧 PNG 的 alpha（保证圆角形状 1:1 不变）；
3. 合成 `plate*(1-t) + mark*t`，再叠细边。

Chrome 命令（沙箱内必须带 `--no-sandbox --disable-gpu`）：
```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --no-sandbox \
  --disable-gpu --disable-dev-shm-usage --hide-scrollbars --force-device-scale-factor=1 \
  --default-background-color=00000000 --window-size=1024,1024 \
  --screenshot=/tmp/mark1024.png file:///tmp/mark1024.svg
```
标记定位参数：1024 画布 `translate(101.4, 229.4) scale(2.878)`；1430 画布 `translate(141.6, 320.3) scale(4.019)`
（等价于留白左右 9.9%、上下 22.4%，两张原图同一套比例）。

改动文件：`assets/images/{icon.png, icon-windows-and-linux.png, logo-apple.png, app_icon.ico}`
+ `dart run flutter_launcher_icons` 生成的 android mipmap / ios / macos / web / `windows/runner/resources/app_icon.ico`。

**托盘图标保持原样**（用户明确要求）：`assets/icons/tray*.png/.ico` 未动。

### 两个坑

1. **`flutter_launcher_icons` 的 `windows.icon_size: 256` 只生成单档 ico**，会把原来的 16/32/48/64/128/256 六档覆盖成只剩 256，任务栏小尺寸靠系统缩图发虚。跑完必须补：
   `cp assets/images/app_icon.ico windows/runner/resources/app_icon.ico`
   已在 `flutter_launcher_icons.yaml` 的 windows 段加注释说明。
2. **`icon.png` 不是纯平色**，底板 R ∈ [45,152]（柔和渐变 + 抖动），标记是纯白。任何「按 R 通道插值混色」的重上色都会在底板留下色偏，
   圆形遮罩边界处尤其明显（会出现一圈可见灰盘）。

### 遗留未做

- **macOS 图标是满版方角**（`logo-apple.png` 本来就满版、alpha 全 255，`app_icon_1024.png` 也是方角），
  换成近白底后，Dock 里会是一块硬边白方片。要修得单独给 macos 备一张「824/1024 内容区 + 圆角 + 投影」的图，
  在 yaml 里给 `macos` 段单独指 `image_path`（iOS 仍是满版）。
- `assets/images/icon-ios.png` 是一张与品牌无关的**圆角播放三角**，未被任何配置或 `lib/` 代码引用，可删。
- `assets/icons/logo.svg` 仍是单色 `#EFEFEF`，只适配深色底；新版标记是深墨色，缺一个 `#0E1B1A` 版。
- 16px 以下仍读不出「V」，纯改色救不回来，需要另做简化标记（合并成两根粗笔画）。

## 收尾：远程艺术家详情的搜索开关也挪到操作行行尾

上节「遗留」已解决。`pages/remote/remote_artist_detail_page.dart`：

- 删掉页头之后那个「右对齐、只放一个 34×34 搜索图标」的 `SliverToBoxAdapter` 内层 Align，
  该 sliver 现在只留 `_buildSearchField`（展开时仍在页头下方占一行）。
- 竖屏页头 Row 3 结构改为 `SizedBox(34) + Expanded(Row(center, 原按钮组)) + toggle`：
  左侧等宽占位让「播放全部 / 随机 / 下载 / 收藏」保持真居中，搜索贴右端。
- 横屏 `_buildLandscapeHeader` 改为 `Row(crossAxisAlignment: start) = Expanded(Wrap(原按钮)) + SizedBox(8) + Padding(top:5, toggle)`。
  `top: 5` 让 34 高图标与 44 高按钮中线对齐；横屏右栏窄时按钮组会换行，搜索仍跟第一行顶部对齐。
- 至此与 `remote_genre_detail_page.dart`（`CollectionDetailHeader(trailingAction:)`）、
  本地艺术家 / 流派 / 年份页一致：**详情页搜索开关固定在操作区行尾最右端**。
