# 2026-10-28

## 缩放条目捏合手势性能优化（0da462bf / 556c6b1a 的收尾）

评审了「双指精确调整缩放档位」两次提交，落地了 P0/P1-3/P2 的一部分。改动 5 个文件 + 1 个测试。

**核心结论（后续别踩）**

- **捏合态必须「懒激活」**：触控板双指滚动走的是同一套 `PointerPanZoom` 事件，只有 `scale` 区分捏合与滚动。
  一旦在 `panZoomStart` / 第二指落下时就把 `FolderZoomPinchController` 设为 active，
  每次滚动都会让 `FolderZoomSliverBuilder` 走捏合分支、整屏可见条目重建（改动前滚动是零重建），
  松手还要多挂 200ms 吸附动画。现在三路指针源（panZoom / 触屏指针表 / 手势识别器）统一走
  `_pushPinchScale()`，只在 `|scale - 1| >= 1e-3` 时激活。`_FolderPinchGestureRecognizer.onStart` 故意不接。
- **`FolderZoomSliverBuilder` 依赖 `FolderZoomPinchScope`，捏合期间每帧都会 `didChangeDependencies`**：
  那里必须 `if (_initialized) return;`，否则每帧白算一次 `_targets()`（原来叠加 build 里的两次 = 每帧 3 次）。
  `didUpdateWidget` 同样要「scale/width 都没变就 return」，父级因播放态/筛选重建时不该重算目标布局。
- **捏合期间两个档位的 target 值在整个手势里固定**，`_cachedTargets()` 按 (width, isPortrait, textScale) 失效缓存。
- **字号插值必须量化**：`fontSize` 每变一点 `RenderParagraph` 就重造 `Paragraph`，
  网格 6~8 列每帧上百次重排版。`quantizeFolderZoomFontSize()` 对齐到 `kFolderZoomFontSizeQuantum = 0.5`，
  一次过渡每个字号只真正变 2~4 次。
- **`isPortrait` 进 `FolderZoomLayoutMetrics`**：条目层（`SongZoomItem` ×2、`ZoomItemScaffold` ×2）不再各自
  `MediaQuery.of(context).orientation`。`build` 里只取一次 MediaQuery，同时传给 `_calculateTargets` /
  `folderZoomGridTextHeightFor()`（纯函数版本，不摸 MediaQuery）。
- `updatePinch` 在「目标档位与 progress 都没变」时直接 return 不 notify（纯平移、重复上报）。
- `endPinch` 在「没跟手位移也没确认换档」时直接收尾，不跑 200ms 动画。
- 回归用例：`test/widgets/folder_zoom_gesture_layer_test.dart` 新增「触控板双指滚动（scale 恒为 1）不进入捏合态，
  画面零重建」，用 builder 调用计数断言。

**未做（用户说等等再说）**

- P1-5：`isGridTarget` 在 progress 50% 翻转 → `ZoomItemScaffold` 根节点换类型（`HoverableCard`）→ 全可见条目 remount；
  建议滞回（>0.55 / <0.45）或手势期间锁档。
- P2-8 双路指针源同一事件算两遍、P2-9 每次手势新建 AnimationController + `_committedScale` 靠两次 postFrame 清理的时序脆弱。

## 网格 ↔ 列表过渡改成「只渲染当前侧一份」（P1-4 的替代方案）

原方案是「只给视口内条目做动画、其余原地淡入淡出」。查证后否决了这个提法：
**屏外条目本来就不存在**——`SliverChildBuilderDelegate` 懒构建，只有视口 + `cacheExtent` 里的条目有 widget，
屏外滚到时已是终态。真正在付钱的是 cacheExtent 里那约 40% 看不见的条目，
而「可见性判定」要每帧算 index 区间并 rebuild 全部可见条目，省下的 render 又还回 build 了。

最终落地的是：**任何时刻只构建当前侧一份内容**，几何插值照旧由 delegate 负责。

- `FolderZoomLayoutMetrics` 新增 `contentIsGrid`（`bool?`）+ `contentReveal`（默认 1.0），
  `renderAsGrid` getter 在 `contentIsGrid` 为空时降级成 `gridMorph >= 0.5`（测试里手工构造 metrics 不传也能用）。
- `_FolderZoomSliverBuilderState._resolveContentHandoff(morph)` 是唯一决策点：
  滞回上下界 `kFolderZoomContentHandoffUpper/Lower = 0.55/0.45`，`_contentSide` 字段跨帧记忆。
  **禁退回单点判定**：手势磨在中点附近会逐帧翻转，每次翻转都是一整套文字重排。
- 交接压暗：`kFolderZoomContentHandoffFadeHalfWindow = 0.12`、
  `kFolderZoomContentHandoffMinOpacity = 0.55`，`reveal = 0.55 + 0.45 * (|morph-0.5| / 0.12)`，
  只有 `reveal < 1` 时才套 `Opacity`（其余时间零额外合成）。
- `song_zoom_item.dart` 的 `_SongZoomContent.build`：原来三分支（纯网格 / 纯列表 / Stack 双份 + 双层 Opacity）
  收成「按 `metrics.renderAsGrid` 二选一 + 单层 `Opacity(contentReveal)`」。
- 回归用例两个：`song_zoom_item_test.dart` 的「跨网格↔列表过渡时只构建当前侧一份内容」
  （列表侧有 `FLAC` 徽标、无合成副标题；网格侧反之；并断言只有一层 opacity=0.7）；
  `folder_zoom_gesture_layer_test.dart` 的「跨「列表↔网格」时内容侧按滞回翻转，不会在中点来回跳」
  （scale 1.52 → morph 0.52 仍列表侧；1.62 翻网格；回缩 1.48 保持网格；1.40 才回列表）。

**注意**：`ZoomItemScaffold` 的结构翻转（`isGridTarget`，P1-5）仍在 `targetZoomScale` 的 0.5 处，
和内容侧 0.55 差 0.05 行程。做 P1-5 时应把两者统一到同一个滞回，别各写一套阈值。
