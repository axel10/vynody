# 2026-11-01

## 目录页换档时「默认图标条目淡入比有封面条目晚一拍」

**现象**：`folder_*` 页档位切换（260ms，`zoom_layout_utils.dart:2293`）时，单侧可见条目走
`ZoomItemScaffold` 的 `Opacity(transition.opacity)` 原地淡入；但显示默认图标的条目要等换档
动画结束才开始自己的淡入。

**根因**（不是缩放引擎）：`song_thumbnail.dart`
- `_checkOrQueryArtwork` 的「已就位」判据只有 `thumbnailPath` / `bytes`。没封面必然不命中 →
  `_isGenerating = true, _needsFadeIn = true` → `build` 里 `isPending` 渲染空 `SizedBox`（空白）。
- 异步 `ArtworkResolver.resolveForThumbnail`（查库 + `findRawArtwork` 解内嵌封面 + 目录封面，
  经 `ThumbnailScheduler` 本地 2–4 槽排队）返回 null 后才渲染 fallback，并且叠加自己的
  280ms `AnimatedOpacity`（`kArtworkFadeInDuration`）。两条时钟不同源 → 肉眼可见晚一拍。
- 有封面的条目走快速路径 → `duration: Duration.zero`，透明度只由条目级 `Opacity` 驱动。

**已改（方案 B）**：解析结果为 null 或异常时 `_needsFadeIn = false`，默认图标直接以 1.0 呈现。
换档未结束时它跟着条目那条曲线一起淡入；已结束则立即显示（无淡入，略生硬，可接受）。
解析期间仍然空白 —— 首次解析慢的情况 B 管不了。

**未采纳（方案 A）**：同步判定「没封面」后立刻出图标。会把它变成「默认图标 → 缩略图」，
且 `artworkPath`/`thumbnailPath` **不是扫描期写的**（`scanner_scan_pipeline.dart:274` 只继承
existing，缩略图是 UI 懒生成），因此「有封面但没懒生成过」与「真没封面」在同步视角完全同形
→ 首次浏览整批条目都会闪一次图标。若将来要彻底消掉空白，正路是目录页预取（批量预热解析）
或把 A 做成图标在底、封面在其上交叉淡入。

**临时诊断日志**：`_queryArtworkAsync` 里打印 `resolve <ms> hit=<bool> <path>`，用来区分
负缓存命中（个位数毫秒）与真解析（几十 ms 以上、且受槽位排队影响）。实测用户确认修复后
已删除（连同 `Stopwatch`）。

## 第二轮：真凶是条目子树重建（不是解析慢）

`run.log`：解析 2–62ms、多数 <25ms，但**同一批路径反复解析** —— 说明条目被反复重建。

**根因**：`zoomable_sliver_grid/lib/src/zoom_item_scaffold.dart` 把三层包装按 `isFadeScale`
条件增删。单侧可见条目（pinned）在过渡**收尾**那一帧从
`Opacity > Transform > ZoomItemEffectiveMetrics > HoverableCard` 塌缩成 `HoverableCard`，
`LayoutBuilder` 之下根类型一变 → 整条子树 deactivate 重建 → `SongThumbnail` 丢 State
（`_isGenerating` 回 true）→ 默认图标先空白一两帧再重新解析。所以：
- 原症状「等换档动画结束默认图标才淡入」= 收尾重建后走完整慢路径 + 280ms；
- 方案 B 之后变成「淡入结束后闪一下」= 收尾重建后空白一两帧。
有封面的条目同样被重建，只是 ImageCache 同步出图，看不出来。

**已改**：三层包装一律常驻，只用数值表达「无过渡」（opacity 1.0 / scale 1.0 /
`metrics: effectiveMetrics`）。代价两个 render object：`Opacity` alpha=255 直接透传不建图层，
`Transform` 单位矩阵只是一次 canvas 变换。
回归：`zoomable_sliver_grid/test/zoom_item_remount_test.dart`（`initState` 计数探针；
回退修复后该测试确实失败）。

**验证标准**：再跑一次目录页换档，同一路径每次换档应只解析一次（不再两遍）。
`test/widgets/folder_zoom_geometry_trajectory_test.dart` 有 5 个既有失败
（`currentFrameTimeStamp != null` 断言，来自子模块 `zoom_layout_utils.dart` 的未提交改动），
与本次改动无关 —— 回退我的改动后同样失败。

## 结果

用户实机确认「不闪了」。收尾：删掉 `song_thumbnail.dart` 里的临时 `debugPrint` 与
`Stopwatch`，`flutter analyze` 无 issue，`song_thumbnail_fade_in_test` /
`song_thumbnail_gapless_test` 7 个用例全过。

## 第三轮：根目录页换档收尾「列表往下沉一点」

复现：`zoomable_sliver_grid/test/scratch_root_page_gap_test.dart`（照根目录页三段结构）；
用探针量段头 / 云端首项的屏幕 y。

数据（列表→网格，滚动中段）：动画最后一帧 637.7/697.7 → 结束帧 645.7/713.7，
即段头 +8、云端列表 **+16**；把段首内边距改成常量 8 则位移 0。短页面 +8/+8。

**根因**：`_ZoomSectionState.gapBefore` 的前提是「`precede − Σ上游段高` 剩下的是
与档位无关的常量」，而根目录页两处 `SliverPadding.top` 自己就是
`lerpDouble(0→8, gridMorph)`（`folder_content_slivers.dart:398`、
`remote_server_slivers.dart:438`）。于是段间隔随档位变，包内按列表档的 gap 换算，
收尾帧切回真实 layout 一次性补 8/16px。

**结论**：不是哪段间隔写错了，是包内那条不变量在该页面不成立。修法见对话：
A（项目侧改常量 8，2 行）/ B1（每帧从 precede 反推 gap → 只治跳变、落点仍偏 δ
且短列表 reachedEnd 时自反馈）/ B2（gap 按档位记录 + 按层权重插值）/ C（页面声明
`sectionGapBuilder`，任意层精确求 pageStart）。

**已按方案 A 落地**：
- `lib/widgets/folder_content_slivers.dart`：`topPad` 由 `lerp(isRoot ? 0 : 8, 8, gridMorph)` → `const 8.0`（顺带删掉不再使用的 `dart:ui` import）。
- `lib/widgets/remote_server_slivers.dart`：同样 `lerp(0, 8, gridMorph)` → `const 8.0`。
- 两处都留了注释说明「段间距必须与档位无关」及其后果，指向回归测试。
- 临时脚本 `scratch_root_page_gap_test.dart` 转正为
  `zoomable_sliver_grid/test/zoom_section_gap_test.dart`（3 条：恒定 gap 短/长页面收尾不跳、
  间距随档位变必跳的已知限制）。
- 验证：包内 `flutter test` 62 项全过；项目 `views_layout_smoke_test` 17 项过；
  `flutter analyze` 两个文件只剩 `onReorder` 的既有 deprecation。
- 代价（已与用户确认接受）：根目录页**列表态**顶部多 8px、云端段上方多 8px。

## 远程目录页（WebDAV / SMB）条目压到 rail 底下

**现象**：`RemoteFolderBrowserPage`（webdav / smb 共用）里网格/列表条目整体左移，
挤进左侧 rail 的范围；卡片同时比本地目录页宽、右侧被裁。

**定位**：`SliverAnimatedZoomGridDelegate` 的横向坐标靠 `_resolveLayerHorizontal()`
折算：`currentHPad = (outerWidth - usableWidth) * 0.5`（假设内容在 `outerWidth` 里
居中），`originOffsetX = targetHPad - currentHPad`。该页的两个 sliver 都没传
`crossAxisExtent`，于是 `width` 退回 `MediaQuery.sizeOf(context).width`（整个窗口）。
窗口减去 rail 后内容更窄且不是居中对称 → 偏移对不上：
- rail 88 / 窗口 1512：`originOffsetX = 8 - 52 = -44`，卡片宽按 1512 算 → 溢出右侧；
- rail 展开更宽时偏移等比例放大，条目直接压到 rail 下。

本地两页（`folder_detail_view` / `folder_root_view`）一直把 `LayoutBuilder` 的
`constraints.maxWidth` 传进 `FolderZoomSliverBuilder.width` 和列表组件的
`crossAxisExtent:`，所以只有远程页出问题。

**修法**（`lib/pages/remote/remote_folder_browser_page.dart`）：
- 主体内容抽成本地闭包 `Widget buildMainContent(double crossAxisExtent)`，
  **在 `LayoutBuilder` 内部**调用 `buildMainContent(constraints.maxWidth)`。
  内容树必须现算——只在 build 里缓存 `_contentCrossAxisExtent` 会一帧滞后
  （首帧/窗口缩放时仍按旧宽度排版 = 同样的错位）。
- 两个 sliver 补 `crossAxisExtent: crossAxisExtent`。
- `git diff -w` 只有 17 行真实改动，其余是整块缩进 +2。

**验证**：`flutter analyze lib` 无 error（仅既有 info）；`views_layout_smoke_test` 17 项过。

**遗留**：该页仍是「两个 `FolderZoomSliverBuilder`」未迁到单 builder + `section`
（换档时下游段会被上游 `ΔH` 顶走）。宽度这条已修好，竖向那条按 `未改` 记在
MEMORY.md 的「一页多段缩放」行。

**顺带**：MEMORY.md 超注入上限被截断，已全文归档到
`MEMORY-archive-2026-11-01.md` 并重写为 13.4KB 版本（同条规则合并、现象细节移入归档）。

## 远程目录页迁到「单 builder + section」（收掉上条遗留）

**目标**：`remote_folder_browser_page`（WebDAV / SMB 共用）原来两个 sliver 各建一个
`FolderZoomSliverBuilder`，换档时上游（子目录）的 `ΔH` 不会被算进下游（文件）的补偿，
下游被顶走一截；两个 builder 还会同写一个 `ScrollPosition`。

**改法**：
- 两个 sliver 改 `FolderZoomSectionHost`（祖先有 `FolderZoomMetricsScope` 就复用页面度量），
  新增 `section` 字段，传给 `SliverAnimatedZoomGridDelegate` + `FolderZoomItem` / `SongZoomItem`
  （两处必须同源，否则冻结的「单侧可见条目」表按段对不上）。
- 页面侧 `FolderZoomGestureLayer → FolderZoomSliverBuilder(controller: _scrollController) → buildMainContent`
  ，section 常量 `_kRemoteFolderSection='remote-browser.folders'`、`_kRemoteFileSection='remote-browser.files'`。
- **性能前提**：`buildMainContent` 现在挂在 builder 里，换档动画每帧都会执行，所以
  `_getAudioFiles(sourceList: displayedItems)` 必须 hoist 到闭包外（原先闭包内被调 4 次，
  每次都要构造 `MusicFile` 并查元数据）。`matchedFolders` / `matchedFiles` / `bannerCoverWidget`
  本来就在外面。
- 加载/错误/空目录三个分支也一起包进 builder（无网格时不记录 tracker，不影响）。

**验证**：`flutter analyze` 无 error；新增 `test/pages/remote/webdav_sections_share_builder_test.dart`
两条（两段共用 1 个 builder / 无页面 builder 时段自我托管）；`test/pages` + `test/widgets` 全过；
`zoomable_sliver_grid` 包 62 项全过。

## 远程目录页空白：builder 挂 controller 在分支切换帧双挂载

**现象**：进远程目录页整片空白；`run.log` 里
`ScrollController attached to multiple scroll views` / `_positions.length == 1`，
抛在 `SliverAnimatedZoomGridDelegate.getLayout → FolderZoomViewportTracker.record →
_FolderZoomSliverBuilderState._scrollPosition()`（`controller.position`），随后是
`RenderSliverEdgeInsetsPadding` 的空指针级联。

**根因**：上一条迁移里给页面级 `FolderZoomSliverBuilder` 传了 `controller: _scrollController`。
本页按 `_isLoading`/`_error`/空目录/有内容分四支，loading/error 是裸 `CustomScrollView`，
另两支套 `RefreshIndicator`。loading → 有内容时 `RefreshIndicator` 插进祖先链，整段
`ScrollView` 换父级 → 新元素重建，旧 `ScrollPosition` 要到本帧 `finalizeTree` 才 detach。
布局发生在 finalize 之前，于是那时 `controller.positions.length == 2`，`.position` 断言炸掉，
sliver 没有 geometry → 整页空白。

**改法**：不传 `controller`（`_scrollPosition()` 走 `_collectViewports` +
`_isAlignedWithLayout` 的对齐校验路径，能容忍这一帧重叠，也正是迁移前两个段内 builder 的做法）。
注意本页 `CustomScrollView` 仍各自持有 `_scrollController`（给 `jumpTo`/定位歌曲用），只是不给 builder。

**验证**：`test/pages/remote/webdav_sections_share_builder_test.dart` 新增第三条
（复刻页面结构：loading 裸 ScrollView → 有内容套 RefreshIndicator），并在 harness 里
临时加回 `controller:` 确认能复现同一条断言（有牙），去掉后通过。

## 播放列表右键唤菜单时远程封面条目闪一下

**现象**：播放列表网格里，右键唤出上下文菜单时，代表歌曲是远程曲目的那几个条目会闪；
本地封面的条目不会。日志在 `run.log`（`[ArtTrace]`）。

**日志判读**（`run.log` 302-383）：
- 右键 → 整个网格的 5 个条目全部 `init` 新 State，随后旧 State `dispose`
  （`init` 先于 `dispose` = 同帧被新元素顶掉），而且连续两代，即整段条目被重建两次。
- 本地条目重建后首个 `branch` 就是 `file`，`pending=false fadeIn=false`；
  远程条目重建后 `pending-blank` → 等 `query-done` → `file` + `fadeIn=true`（280ms）。
- 所以「闪」= 重建（State 丢，重新走进待解析分支）+ 远程封面**没有同步解析路径**
  （`ArtworkResolver.resolveForThumbnail` 虽然命中内存缓存，但返回 Future，结果隔一个微任务
  才回到 widget，首帧已经画成空白）。

**改法**：
- `ArtworkResolver.peekCachedThumbnail({path, thumbnailPath})` 新增同步入口（直接复用
  `_tryCachedThumbnail`，含 `_verifiedPaths` 免 stat 与文件存在校验）。
- `SongThumbnail._checkOrQueryArtwork` 在「bytes 快速路径」之后探一次：命中即设
  `_artworkFilePath` + `_isGenerating=false`，`fromInitState` 时 `_needsFadeIn=false`，
  不再进待解析分支。这样任何来源的重建（右键、换档收尾、行回收）首帧就有图、无淡入。
- 回归：`test/widgets/song_thumbnail_fade_in_test.dart` 新增「已解析过封面的曲目被重建时
  首帧直接出图（不空白、不淡入）」（先 `resolveForThumbnail` 预置缓存，再只按 path 挂载）。

**结果**：用户实机验证「已经不闪了」。

**遗留（暂不追）**：右键时这 5 个条目为什么会整段重建两次，静态阅读没定位到根因
（页面级没有现成的条件换根；`ZoomItemScaffold` 的三层包装已常驻；`HoverableCard`/
`ZoomItemCover` 结构稳定）。同步缓存让它在观感上消失，但 State 仍丢（hover、
`_keepLastFrame` 会重置）。等再出问题时按这个顺序查，别从零开始：

1. `SongThumbnail.initState` 里 `context.visitAncestorElements` 收集
   `Type#elementHash` 链（`toList().reversed`），存静态字段，与上一次挂载的链逐层比对，
   打出**第一个变化的层** —— 一次右键就能指到重建边界。
2. 边界出来后看该层 build 是否按条件换了根类型 / key，或 sliver 前面是否插删了兄弟段
   （`SliverPadding(sliver: SliverGrid)` 位置一挪，整段子树就会重建）。
3. 判据：`init` 早于 `dispose`（同帧）＝被新元素顶掉；只有 `didUpdateWidget` ＝ 只是重建。
   `[ArtTrace]` 那套日志已全部撤掉，需要时按上面形状重加。

## 播放列表多选：空歌单的删除按钮被灰掉（已修）

**现象**：播放列表总览页（`lib/pages/playlist_tab.dart`）里多选一个**空歌单**，
底部 `LibrarySelectionPanel` 的「删除歌单」按钮是灰的，点不动。

**根因**：两个判空口径打架。面板里删除按钮可用性是
`isEmpty ? null : widget.onDelete`，而 `isEmpty = widget.isSelectionEmpty ?? selectedSongs.isEmpty`。
本页多选对象是**歌单实体**，但传给面板的 `selectedSongs` 是「被选中歌单里所有歌」
平铺后的结果 —— 空歌单展平后为空列表，于是被判成「没选中任何东西」。
而 `onDelete` 本身已用 `isCustomPlaylists.isNotEmpty` 判过可删性，两套口径互相否决。

**改法**：`playlist_tab.dart` 给面板补 `isSelectionEmpty: selectedKeys.isEmpty`
（选择集合是歌单 id，字面语义正确，也是 `remote_library_page.dart` 已有的用法）。
只放开删除：面板里其余按钮都还有 `isSongSelectionEmpty` 兜底
（playNext / addToQueue / addToPlaylist / 收藏 / 编辑标签 / 转码），不会跟着误亮。

**遗留（已识别，未改）**：面板「全选」按钮的禁用条件仍看 `widget.allSongs.isEmpty`。
若库内所有歌单全为空，`allSongs` 为空 → 全选按钮照样灰、全选态文案也判不出。
要修得给面板引入「可选实体数」的概念，别再用歌曲平铺数替代。

**补改（同一轮，用户要求连带修）**：`LibrarySelectionPanel` 新增
`hasSelectableItems`（`bool?`）。全选按钮可用性改为
`widget.hasSelectableItems ?? (allSongs.isNotEmpty || isAllSelected != null)`，
未传时与旧条件 `!(allSongs.isEmpty && isAllSelected == null)` 完全等价，
其余页面行为不变。`playlist_tab` 传 `hasSelectableItems: playlists.isNotEmpty`
与 `isAllSelected: playlists.isNotEmpty && selectedKeys.length == playlists.length`
（与 controller `toggleSelectAll` 的长度判据保持一致）。
顺带修掉「只选中那个包含全部歌曲的歌单时误显示已全选」——歌单之间共用歌曲是常态，
专辑/艺术家之间不共用，所以只有歌单页需要显式传 `isAllSelected`。
