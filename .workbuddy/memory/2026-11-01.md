# 2026-11-01

## 目录页换档时「默认图标条目淡入比有封面条目晚一拍」

**现象**：`folder_*` 页档位切换（260ms，`zoom_layout_utils.dart:2293`）时，单侧可见条目走
`ZoomItemScaffold` 的 `Opacity(transition.opacity)` 原地淡入；但显示默认图标的条目要等换档
动画结束才开始自己的淡入。

**根因**（不是缩放引擎）：`song_thumbnail.dart`
- `_checkOrQueryArtwork` 的「已就位」判据只有 `thumbnailPath` / `bytes`。没封面必然不命中 →
  `_isGenerating = true, _needsFadeIn = true` → `build` 里 `isPending` 渲染空 `SizedBox`（空白）。
- 异步 `ArtworkResolver.resolveForThumbnail`（查库 + `findRawArtwork` 解内嵌封面 + 目录封面，
  经 `ThumbnailScheduler` 本地 2–4 槽排队）返回 null 后才渲染 fallback，并且叠加自己的
  280ms `AnimatedOpacity`（`kArtworkFadeInDuration`）。两条时钟不同源 → 肉眼可见晚一拍。
- 有封面的条目走快速路径 → `duration: Duration.zero`，透明度只由条目级 `Opacity` 驱动。

**已改（方案 B）**：解析结果为 null 或异常时 `_needsFadeIn = false`，默认图标直接以 1.0 呈现。
换档未结束时它跟着条目那条曲线一起淡入；已结束则立即显示（无淡入，略生硬，可接受）。
解析期间仍然空白 —— 首次解析慢的情况 B 管不了。

**未采纳（方案 A）**：同步判定「没封面」后立刻出图标。会把它变成「默认图标 → 缩略图」，
且 `artworkPath`/`thumbnailPath` **不是扫描期写的**（`scanner_scan_pipeline.dart:274` 只继承
existing，缩略图是 UI 懒生成），因此「有封面但没懒生成过」与「真没封面」在同步视角完全同形
→ 首次浏览整批条目都会闪一次图标。若将来要彻底消掉空白，正路是目录页预取（批量预热解析）
或把 A 做成图标在底、封面在其上交叉淡入。

**临时诊断日志**：`_queryArtworkAsync` 里打印 `resolve <ms> hit=<bool> <path>`，用来区分
负缓存命中（个位数毫秒）与真解析（几十 ms 以上、且受槽位排队影响）。实测用户确认修复后
已删除（连同 `Stopwatch`）。

## 第二轮：真凶是条目子树重建（不是解析慢）

`run.log`：解析 2–62ms、多数 <25ms，但**同一批路径反复解析** —— 说明条目被反复重建。

**根因**：`zoomable_sliver_grid/lib/src/zoom_item_scaffold.dart` 把三层包装按 `isFadeScale`
条件增删。单侧可见条目（pinned）在过渡**收尾**那一帧从
`Opacity > Transform > ZoomItemEffectiveMetrics > HoverableCard` 塌缩成 `HoverableCard`，
`LayoutBuilder` 之下根类型一变 → 整条子树 deactivate 重建 → `SongThumbnail` 丢 State
（`_isGenerating` 回 true）→ 默认图标先空白一两帧再重新解析。所以：
- 原症状「等换档动画结束默认图标才淡入」= 收尾重建后走完整慢路径 + 280ms；
- 方案 B 之后变成「淡入结束后闪一下」= 收尾重建后空白一两帧。
有封面的条目同样被重建，只是 ImageCache 同步出图，看不出来。

**已改**：三层包装一律常驻，只用数值表达「无过渡」（opacity 1.0 / scale 1.0 /
`metrics: effectiveMetrics`）。代价两个 render object：`Opacity` alpha=255 直接透传不建图层，
`Transform` 单位矩阵只是一次 canvas 变换。
回归：`zoomable_sliver_grid/test/zoom_item_remount_test.dart`（`initState` 计数探针；
回退修复后该测试确实失败）。

**验证标准**：再跑一次目录页换档，同一路径每次换档应只解析一次（不再两遍）。
`test/widgets/folder_zoom_geometry_trajectory_test.dart` 有 5 个既有失败
（`currentFrameTimeStamp != null` 断言，来自子模块 `zoom_layout_utils.dart` 的未提交改动），
与本次改动无关 —— 回退我的改动后同样失败。

## 结果

用户实机确认「不闪了」。收尾：删掉 `song_thumbnail.dart` 里的临时 `debugPrint` 与
`Stopwatch`，`flutter analyze` 无 issue，`song_thumbnail_fade_in_test` /
`song_thumbnail_gapless_test` 7 个用例全过。
