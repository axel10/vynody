## mesh_flow 背景「蓝色比原图任何部分都艳」根因定位

`mesh_flow/lib/src/cover_processor.dart` `_applyColorTuningAndBlur()` 是**在 gamma 编码 sRGB 值上做的一串乘性变换 + 逐通道 clamp**，净色度系数可算成常量：

```
0.5(预压缩) × 2.6(saturation) × 1.4(contrast) × 0.8(kBright) ≈ 1.456
```

即 `saturation: 2.6` 实际只给 **×1.46 的 Lab 色度**，但它对所有像素一视同仁，再叠加 `:262-264` 逐通道 `clamp(0,255)`，暗色相有大量向上余量 → 深色大面积区域吃满增益。

实测（OneRepublic - Take Care Of You 封面，32×32 降采样 + 完整管线复算）：

| 指标 | 原图 | 调色后 |
|---|---|---|
| 整张最高 C* | 73.6（粉云 rgb(227,96,211)） | 100.2（天空蓝紫 rgb(151,64,241)） |
| 天空区峰值 C* | 63.3 rgb(65,87,192) | 91.3 rgb(43,75,228) |
| 天空区平均 C* | 44.0 | 62.8 |
| 通道跌出 [0,255] 被硬 clamp | — | 229/1024 (22%) |

「蓝色最艳」= 蓝是 61% 面积的大块平坦区（4×boxBlur 摊薄不掉）+ 增益后峰值 100 > 原图全局峰值 73.6，越过了原图自身的饱和上限。青雾 `rgb(70,196,196)` 的 R 算出 **-9** 被 clamp 成 `rgb(0,174,174)`、S 顶到 1.00，是同一根因的极端表现。叠加 v2 暗色层默认 0，蓝色不被压。

参数参考（深蓝 rgb(65,87,192) 的 C*）：saturation 2.6→91.3 / 2.0→71.2 / 1.8→64.8 / 1.6→57.8 / 1.4→51.3。建议 1.6~1.8；根治要补「色域回缩」（超界时整体缩色度，而不是单通道 clamp）。

## 落地修复：saturation 默认 2.6 → 1.8 + 色域回缩

- `cover_processor.dart`：三处默认值 `saturation = 2.6` → `1.8`；`mesh_flow_widget.dart` 同步（`MeshFlow.saturation` 默认 + 字段文档改成写清净系数公式）。
- 新增 `_gamutFit` / `_gamutFitChannel`：算出浮点 RGB 后若通道越界，**沿亮度轴 anchor 整体收缩色度**（anchor = 该像素零色度时的输出值，即 `((gray-128)*contrast+128)*kBright`），取代原来的逐通道 `clamp`。色相与亮度保住，不再出现 `rgb(0,174,174)` 这种 S=1.0 纯色块。
- 真实管线实测（同一张封面，`processBytes` 导出 32×32 贴图后统计）：

| | 平均 C* | 最大 C* | C*≥65 像素 | 最青像素 |
|---|---|---|---|---|
| 旧 2.6 | 57.0 | 89.4 rgb(42,72,221) | 420/1024 | rgb(3,154,173) |
| 新 1.8+回缩 | 40.9 | 63.4 rgb(55,74,177) | 0/1024 | rgb(31,143,155) |

  原图 32×32 的最高 C* 是 73.6 —— 新版不再越界。
- 新增 `mesh_flow/test/cover_processor_test.dart`（3 条）：深蓝天空色度涨幅 <10% 且色相守恒；青雾最暗通道 >15（不被砸成纯青）；色域外输入（纯青）色相误差 <2°、无通道贴 255。跑测前记得清代理变量。
- **约定**：`saturation` 不是最终倍率，净系数 = `0.5 × saturation × 1.4 × 0.8 = 0.56×saturation`；1.8 ≈ 中性。想留一点提味取 2.0（净 ×1.12），别越过 2.2。


## 浮动 Dock 收起动画：整行上下裁切 → 多图标左移合流成一个

`lib/widgets/floating_dock_bottom_bar.dart`

- 旧实现：Tab 行外套 `ClipRect + Align(heightFactor: 1-t)` 从下往上裁掉，配 `Transform.translate(-24*i*t)`
  的手风琴左推，观感是「整行图标在上下位移」。
- 新实现（`_buildBottomTabs`）：`Stack(clipBehavior: Clip.none)` + 每个图标 `Positioned`，逐图标
  `Transform.translate` 到收起态胶囊那个单图标的中心（左移 + 上移）+ `Transform.scale(1-0.45t)`
  + 各自淡出（当前 Tab 的图标最后淡且画在最上层 = 被它吸收）。展开是同一条轨迹反向播放。
- 合流目标点必须跟着 t 走：`-(进度条高*(1-t) + header高(t)/2)`（相对 tab 行左上角）。写死常数值会差
  约 25px（header 在收起过程中随布局下移 80px），图标会停在空处而不是落进那个图标。
- 外层 `ClipRect` 必须去掉：Align 只压缩布局高度、不裁剪，图标才能平移出这一行；越界由最外层
  `ClipRRect` 兜底。命中区仍靠 `IgnorePointer(ignoring: t > 0.2)`。
- 几何常量收敛到文件头 `_dockHeaderHeight / _dockHeaderPaddingH / _dockCapsuleIconWidth /
  _kDockProgressStripHeight`，header 与 tab 行共用，禁止再写字面量。
- 时机：外层 `TweenAnimationBuilder` 用 `easeOutCubic`（前 1/3 时间走掉大半进度），所以位移
  `converge` 要在 `t/0.62` 内收完、淡出排在 0.30→0.72，否则「刚开始飞就看不见了」。
  微调入口就是这三个数。
- 回归测试：`test/widgets/floating_dock_bottom_bar_test.dart` 新增逐帧采样用例（相邻图标间距收敛到
  <8px、落点与胶囊图标 x 差 <6px、展开后回到原槽位）。
