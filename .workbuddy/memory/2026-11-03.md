# 2026-11-03

## 修复：翻译歌词流式生成时，每出一行所有已生成译文行重播进入动画

**现象**：AI 歌词翻译边流式产出边显示时，每来一行新译文，之前已经淡入完毕的所有译文行
都会重新播一次 `AppleLyricTranslationFadeIn` 的淡入＋上浮。

**定位**（临时探针 `[LyricsFadeProbe]`，跑一遍复现后已全部删除）：run.log 里
`translatedLines=null` 的帧与 `[LyricsController] lyrics cache watch applied ...
translationsFromDB=[] (recordsCount=0)` 一一对应，紧接着就是一批 `trans init idx=0..N`
＋同批 `dispose`。即整份译文在某一帧被清空，下一帧又被流式同步填回来 → 每行淡入 State
重建 → 动画重播。链条：

1. 每个 chunk → `_syncTranslatedLyricsToSong` → `unawaited(_saveTranslatedLyricsToDatabase)`
2. 写库走 `insertOrUpdateLyricsTranslationCache` 的**「先按 (cacheKey, languageCode) 删除、
   再 insert」**
3. 删与插之间的空窗里 `watchLyricsTranslationCaches()` 给订阅方吐一份 **空列表**
4. `_syncLyricsCacheWatch` → `applyLyricsRecordToCurrent(translations: {})` 整份覆盖内存译文
5. 下一帧 chunk 又把译文填回来 → 所有行 State 重新 init

顺带查出两个真 bug：

- `insertOnConflictUpdate()` 生成的冲突目标是主键 `id`，命中不了 `UNIQUE(cacheKey, languageCode)`；
  并发/交错写入直接 `SqliteException(2067) UNIQUE constraint failed`（日志里反复出现）。
- 流式快照本身偶尔比上一帧少一行（`LyricsAiTranslationTextHelper.visibleTranslationText`
  按「去掉末尾半行」裁切 + 空行重排），那一行的译文会消失一帧再回来，同样触发单行重播。

**改动**：

- `metadata_drift_database.dart::insertOrUpdateLyricsTranslationCache`：改成一条原子
  `insert(companion, onConflict: DoUpdate(..., target: [cacheKey, languageCode]))`，
  没有 delete 空窗，也没有 UNIQUE 冲突。
- `lyrics_controller_utils.dart::applyLyricsRecordToCurrent`：新增
  `_mergeTranslationsWithoutRegression` —— 按语言取「非空行数更多」的一方；翻译进行中
  DB 快照缺这门语言时沿用内存版本。
- `lyrics_controller_translation.dart::_syncTranslatedLyricsToSong`：流式阶段
  (`bumpLayoutRevision == false`) 用 `_mergeStreamingTranslatedLines` 把「新快照变空但上一帧
  有内容」的行补回旧值；收尾那次仍整份覆盖。

**回归**：`test/player/lyrics_translation_cache_watch_test.dart`
（① watch 流一旦有过数据就不得再回到空；② 并发写不抛 UNIQUE、后写者生效）。
已验证这两条在旧实现下**都会失败**，新实现下通过。`flutter analyze` 干净；
`music_lyric` / `lyrics_entry_flow` / `lyrics_panel_logic` 全绿。

**环境备注**：跑 `flutter test` 会让 `pubspec.lock` 的 flutter_taglib 从 `path:` 翻成
override 里的 `git ref: master`（已 `git checkout` 还原，与本次修改无关）。

## 翻译行「跳行时重播淡入动画」—— 行包装层缺 key 稳定性

**现象（修复上一轮之后的新报障）**：翻译流式生成中，播放推进到下一行时，已经出现的
译文行会重新播一次淡入/上浮。

**定位依据**：旧探针日志计数 `stagger init = 56`、`stagger restart = 0`、`line init = 0`。
restart 为 0 说明不是滚动补偿重启动画，而是 **Staggered 的 State 被反复重新 init**
（重建），连带行内 `AppleLyricTranslationFadeIn` 丢 State。`line init = 0` 说明翻译期间
`isGenerationBusy` 恒 false（`AppleLyricLineFadeIn` 从未实例化），所以 `isGenerating`
那条分支不是本次元凶。

**根因**：`lyrics_panel_views.dart` 行构建里

```dart
final bool isInStaggerRange = !widget.isGenerating && widget.isFocusMode &&
    index >= widget.firstVisibleIndex - 10 && index <= widget.firstVisibleIndex + 30;
if (isInStaggerRange) { resultWidget = StaggeredAppleLyricsScrollWrapper(...); }
else { resultWidget = contentWidget; }
```

窗口边界跟着 `firstVisibleIndex` 走，跳行/滚动时边界平移 → 进出窗口的行子树根类型变化
→ 整行 Element 重建 → 译文重播。（Apple 歌词 `_isFocusMode` 默认 true，所以常态触发。）

**修法**：

- 行构建：`StaggeredAppleLyricsScrollWrapper` **常驻**，范围只作为 `enabled` 参数。
- 组件：新增 `enabled`；`AnimationController` 惰性创建，`enabled=false` 时
  `_releaseController()` 释放 ticker 只留空 State；`enabled` 由 false→true 时补建并
  `_startAnimation()`。
- `SingleTickerProviderStateMixin` 必须换 `TickerProviderStateMixin`（惰性重建会出现
  第二个 ticker，否则 assert「multiple tickers were created」）。
- build 结构必须恒定 `ExcludeSemantics > AnimatedBuilder > Transform > child`：未启用时
  用 `AlwaysStoppedAnimation(0.0)` 占位，**禁**在 offset==0 时省掉 Transform —— 少一层
  就是 child 换父级，照样重建（第一版就踩了，测试直接抓到）。

**回归**：`test/widgets/lyrics_staggered_wrapper_test.dart`（① enabled 反复翻转时探针
initState 计数恒为 1；② enabled=false 时不产生任何位移）。
`flutter analyze` 仅剩原有 5 条 `dead_code`；`lyrics_panel_logic` / `music_lyric` /
`lyrics_translation_cache_watch` 合计 17 个测试全绿。

## 译文「跳行重播」真凶：焦点模糊层的类型切换

**现象**：行包装层常驻之后问题仍在。用户点名两句（index 9 `We don't talk much, not anymore`、
index 10 `Broken bottles and slammin' doors`）——播到下一行时该行译文又淡入一次。

**日志判读（`[Tprobe]`）**：

- `view-init` 只有 1 次 → view State 一直存活。
- 69 次 `stagger-init` 全部落在 270-406 这一连续段 → 是**首次构建**，不是重建。所以
  上一轮的常驻修复本身是对的，本次不是它。
- 关键一行：`trans-init idx=9 active=9 animate=true size=true`，而它**前面没有任何
  `slot idx=9` 翻转** → 译文内容没变、行结构没变，纯粹是行内子树被重建。
- 同时 `trans-init idx=8 active=9 size=false`（模糊从 0 → 正数，size=false 所以不播）。
- `trans-animate true->false` 69 次 = 行总数，翻译结束那一帧所有行各报一次，属正常。

**根因**：`lyrics_panel_views.dart` 逐行模糊包装

```dart
builder: (context, blurSigma, child) {
  if (blurSigma <= 0.0) return child!;          // 裸 child
  return ImageFiltered(imageFilter: ..., child: child);  // 多一层
}
```

`targetBlur` 依赖 `|index - activeIndex|`。跳行时新当前行从「正数」动画到 0、上一行从
0 动画到正数，**只要越过 0 这一步，父级 widget 类型就变了**（`ImageFiltered` ↔ 裸 child）
→ 整行 Element 重建 → `AppleLyricTranslationFadeIn` 丢 State → 重播。这也解释了为什么
每次跳行只重建 1~2 行（跨 0 边界的那两行），以及屏幕外行进入视口时也会重建（blur 0 → 正数）。

**修法**：builder 恒定返回 `ImageFiltered`（sigma 为 0 也保留该层）。

**验证**：新增 `test/widgets/lyrics_line_blur_stability_test.dart`——直接构造
`LyricsPanelTimedLyricsView`（activeIndex 1 → 2），用 `identical(state_before, state_after)`
断言第 2 行译文 State 未重建。已用旧写法回跑确认**会失败**（日志复现
`trans-init idx=2 active=1` → `trans-init idx=2 active=2`），新写法通过。
`flutter analyze` 仍只剩原有 5 条 `dead_code`，5 个文件 18 个测试全绿。

**探针保留**：`lyrics_panel_views.dart` 里 `[Tprobe]` 打点先不删，等用户复现确认后再清。

**收尾**：用户确认已修好。已清掉全部 `[Tprobe]` 打点与配套的 `_probeSlotHadText` /
`_probeActive` / `_probeLang` 字段，`flutter analyze` 只剩原有 5 条 `dead_code`；
`lyrics_line_blur_stability` / `lyrics_staggered_wrapper` / `lyrics_panel_logic` /
`music_lyric` / `lyrics_translation_cache_watch` / `lyrics_entry_flow` 共 25 个测试全绿。
