## Windows 切歌内存上涨诊断（结论：无泄漏）

- 现象：任务管理器「内存」随切歌单调上涨、久不回落，本地曲目第一首就开始。
- 工具：新增 `scripts/mem_watch.py`（VM service 堆指标 + Win32 PROCESS_MEMORY_COUNTERS_EX
  合并采样，2s 一点）。用法 `python scripts/mem_watch.py --url <VM service URL> --interval 2`；
  URL 从 `dart.exe development-service --vm-service-uri=` 的命令行里取（flutter run 的
  控制台输出拿不到时可用）。
- 判据（照这个读，别再猜）：rss 分段均值走平 → 无泄漏；private 多次精确回落到起点 →
  是 Windows 堆高水位/分配器不归还，不是活对象累积。Dart 堆锯齿 + external≈0 → Dart 侧干净。
- 实测 499s：Dart heap 97~113MB 锯齿；rss 分段均值 482.9→489.6→500.4→510.0→505.1→505.4，
  400s 后完全走平；private 565~757 来回摆并 7 次回到 565~575；句柄 1700→1700、线程 148→149。
- 用户看到的 365MB 是任务管理器「内存」列（Private Working Set），比 WorkingSetSize 少约 140MB
  共享 DLL 页；两个数不是一回事。
- 已知峰值源（未修，属有界浪费）：`generate_track_artwork` → `build_thumbnail`
  （`audio_core/rust/src/api/simple/metadata.rs:246`）先全尺寸解码再 resize 到 500px。
  3.8MB / 3000x3000 封面解成 RGBA ≈36MB，正对日志里 `queueProcessor:artworkTheme` 那次 +33MB。
  zune 0.5 的 `DecoderOptions` 不支持限尺寸，要压峰值得手动读 JPEG 头走降采样解码，需重编 Rust。
- 诊断探针（`audio_service.dart` 的 `_memoryBreakdownDetails` 与 `audio:switchTrack` 快照）
  已全部删除，`git diff` 干净；`audio:prepareArtwork:end` 恢复原样仍保留 queue 字段。

## 修复：相邻短句被误合并成逐字歌词（`LrcUtils`）

- 现象：`[01:16.09]生きて` 与 `[01:17.03]息をして` 被并成一行 `生きて息をして` 并带 `words`
  （渲染成逐字）。DB 证据 `lyrics_cache` id=561（source=manual_adjust）的 `syncedLinesJson`。
- 根因：`_groupWordPerLineIfNeeded` 原为适配 Apple Music `<mm:ss.xxx>` 每行一词格式，
  判据「文本 ≤4 字 + 相邻间隔 ≤1200ms + 文本不同」，普通行级同步 LRC 的相邻短句同样满足（940ms）。
- 修法：新增 `_isWordPerLineBlock()`，仅当整个 block 的时间戳都是 `<...>`（允许无文本占位行）
  才走 word-per-line 合并；`[mm:ss.xx]` 行级同步歌词进 `allParsedLines` 时不再合并。
- 测试：`test/utils/lrc_utils_test.dart` 新增两条回归（相邻短句不合并、`[..]` 与 `<..>` 混排不合并），
  34 例全过；用真实歌词文本验证修复后 38 行、全无 `words`。
- 遗留：`lyrics_cache` 存的是序列化行（读取不重解析），坏记录需重新解析一次才会更新。

  `isRemoteUri` 一刀切（`:637`）、`File.exists()`（`:534`）、`RemoteMediaResolver.fetchLyrics`
  （`remote_media_resolver.dart:625`）。三协议实际层数不同：本地 = 内存→缓存→旁挂 lrc→内嵌→在线；
  WebDAV = 内存→缓存→远端 lrc→在线；SMB = 内存→缓存→在线。
- 顺序/优先级 5 处副本（fetchBestLyrics、getOrPopulateAvailableLyricRecords、
  kLyricsSourcePreferenceOrder、换源弹窗循环、pickPreferredCacheRecord），来源映射 3 套，
  default 均落 lrclib。
- 远程内嵌可行性确认：fork 的 `taglib_bridge_open_http` + `properties` 走 HTTP Range，
  `TagProperties.lyrics = 'LYRICS'`；SMB 经 `LocalStreamProxy` 206 代理变 HTTP。缺的只是
  `BatchTagMetadata` 无 lyrics 字段、`_readSingleFileMetadataMap`（`:1791`）未采 LYRICS。
  **远程内嵌不需要整首下载**。
- 两条硬约束写进文档：扫描阶段禁直接写 `lyrics_cache`（会命中缓存层、打破 lrc 优先）；
  远程内嵌必须用 `readError` 区分「没有」与「没读到」，后者禁写空缓存。
- 产出 `docs/歌词来源统一-现状与改造计划.md`：现状表 / 痛点 P1-P13 / 目标 `LyricsResolver` +
  `LyricsSourceProvider` / 三阶段改动 / 验收标准 / T1-T23 分解。待确认后先做阶段一（抽象落地、行为不变）。
- 追加：媒体库服务端歌词（Navidrome/Subsonic、Jellyfin）统一并入本次范围，不再作为"后续"。
  两家现状差异 —— Subsonic 两级降级（getLyricsBySongId → getLyrics.view）、已处理无时间轴；
  Jellyfin 单接口、`Start` 全 0 仍拼假逐行（`jellyfin_client.dart:1135`，现存 bug）、
  `authenticate()` 在 try 外（`:1113`）。两家都 `catch (_) {}` 吞异常、无能力缓存、无 cancelToken。
  契约定为四态 `MediaServerLyricsStatus`（hit / absent / unsupported / failed），
  `failed` 不入能力缓存；Subsonic 错误码保守映射（404/未知方法 → unsupported，70 → absent，50/超时 → failed）。
  `_remoteLyricsFetcher` 签名缺 `CancelToken`，是切歌后请求残留的根因。

## 歌词来源统一：阶段一落地（抽象 + 顺序集中）

- 新增 `lib/player/lyrics/sources/`：`lyrics_source_provider.dart`（接口）、
  `lyrics_resolver.dart`（顺序中心）、`sidecar_lrc_provider.dart`、`embedded_tag_provider.dart`、
  `media_server_lyrics_provider.dart`。
- `LyricsService.fetchBestLyrics` 改为委托 `LyricsResolver.resolve`（原始键缓存 → 规范化键缓存 →
  providers 顺序 → 在线兜底），文件净减 429 行（-490/+61）；`_tryLoadFromLocalLrcFile` /
  `_tryLoadFromMetadata` 退化为 provider 委托，仅供换源候选复用。
- **不变量**：来源顺序 = `LyricsService` 构造里 providers 列表顺序，缺省
  `[mediaServer, sidecar, embedded]`，与改造前判定次序逐条对应；在线层仍在 service 内
  （`_resolveOnline`，保留 `_inFlight` 合并），因评分逻辑复用 `_client` 私有方法。
- Resolver 由 service 内部创建而非 riverpod 注入（在线兜底反向依赖会成环）；可注入的是
  `providers` 列表。
- 验证：`flutter analyze lib` 无 error（存量 warning 与本次无关）；
  `test/player/lyrics_*` + `test/widgets/lyrics_panel_logic_test.dart` 共 50 项通过；
  新增 `test/player/lyrics_source_resolver_test.dart` 5 项（列表顺序、不适用跳过、全 miss 走在线、
  缓存命中短路），需 fake `PathProviderPlatform` 才能真读 drift 库。
- 阶段二未动：SMB/WebDAV 后端、远程内嵌 Range、媒体库四态契约都还在计划里。

## 歌词来源统一：阶段二落地（能力对齐 + 媒体库四态）

- 旁挂 lrc：`SmbClient.readTextFile`（pool.readFile + utf8 宽松解码）；
  `RemoteMediaResolver.fetchSidecarLrc`（webdav 走 getFileContent、smb 走 readTextFile）；
  `SidecarLrcProvider` 本地/远程共用一份解析落库，远程 result.source = `remote_lrc`
  （`fromExternalSourceTag` 与 fetchAndLog 的 switch 已同步）。
- 远程内嵌：fork `BatchTagMetadata` 加 `lyrics` 字段 + `_readSingleFileMetadataMap` 经
  `properties_get` 采 `LYRICS`/`UNSYNCEDLYRICS`（Range 读取，不下载整首）；
  `RemoteMediaResolver.fetchEmbeddedLyrics` 复用 `readMetadataAsync`；
  `EmbeddedTagProvider` 本地/远程共用 `_commit`。`readError && 空歌词` 只记日志不落库。
- 媒体库四态：`MediaServerLyricsStatus`(hit/absent/unsupported/failed) +
  `MediaServerLyricsResult`；`SubsonicClient.fetchLyricsResult`（替换 getLyrics）、
  `JellyfinClient.fetchLyricsResult`（替换 getLyrics）；`MediaServerCapabilityCache`
  只记 unsupported，连接测试成功即 clear。
- 修掉两个存量 bug：Jellyfin `Start` 全 0 拼假逐行（现输出纯文本，`_parseLyricsLines`）；
  Jellyfin `authenticate()` 在 try 外导致认证异常裸抛。
- `CancelToken` 已贯通 `_remoteLyricsFetcher` → provider.load → resolver → `_getSubsonicData` /
  Jellyfin `_dio.get`；`SubsonicException` 增 `httpStatus`（404 判 unsupported）。
- 顺序不变：`[mediaServer, sidecar, embedded]` → 在线。媒体库 handles 收敛为
  `subsonic://` / `jellyfin://`，webdav 归到 sidecar。
- 验证：`flutter analyze lib` 无 error（141 条存量 info/warning 持平）；
  歌词/远程相关测试 136 项通过；新增 `test/player/lyrics_remote_sources_test.dart` 17 项。
- 已知偏差：variant 只进日志未进快照描述；`MediaServerLyricsSource` 未单独抽类。
- 阶段三未做：删 `kLyricsSourcePreferenceOrder` 副本、扩来源枚举、清理 `SmbFile.isLyric`。
