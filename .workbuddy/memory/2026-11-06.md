## 滚动波形 30fps 限流（用户确认「减到30帧看看」）

**改动**（`lib/widgets/waveform_progress_bar.dart`，仅 15 行）：
- 新增唯一帧率开关 `static const Duration _kScrollingFrameInterval = Duration(milliseconds: 33)`（33ms 而非 33333µs：60Hz 下 2 帧=33334µs 达标、120Hz 下 4 帧=33332µs 也达标，不会退化成 24fps）。
- `_onTick` 开头门控：距上次发布不足 33ms 直接 return，**且不更新 `_lastFrameTime`**。这一句是正确性关键 —— 若跳过帧也刷新时间戳，delta 只覆盖单帧，进度会按约 1/3 真实时间走慢。Ticker 仍按 vsync 回调，靠「不写 `_smoothProgressNotifier` → 不 markNeedsPaint → raster 复用 retained layer」降整帧合成次数。
- `didUpdateWidget` 的 seek/快照同步不走 `_onTick`，不受门控影响；拖动、惯性、长按快进的手势写值同理。lerp 0.05 校正频次减半，稳态插值超前从约 0.3s 增至 0.6s，波形是相对位移，无感，未改。

**测试**（`test/widgets/waveform_progress_bar_test.dart` 新增 2 条，共 9 条）：监听 `WaveformPainter.progressNotifier` 数出真实 repaint 次数（60 帧×16ms 应 < 35 次）；用 20s 短曲目放大「丢 delta」差异，断言 960ms 后进度增量在 (0.015, 0.05)；另一条验证限流运行中跳转仍能立即 snap 到 0.6。

**验证**：两文件 `flutter analyze` → No issues found；`flutter test` 9 条全绿。

**待用户实测**：滚动模式 GPU 是否大致减半、30fps 平移有无顿挫。若 GPU 没降，说明空转 Ticker 仍在 scheduleFrame 并触发整帧提交，下一步要把 Ticker 换成 30Hz `Timer.periodic` 真正替换驱动源（会动到 createTicker/dispose/测试的 pump 节奏）。当前改动未提交。

## 门控方案被实测推翻 → 滚动模式彻底改用 Timer 驱动

**用户实测**：把 `_kScrollingFrameInterval` 改成 `Duration(milliseconds: 1000)`（1 秒才发布一次 notifier），GPU **仍是十几**。

**决定性结论**：上一轮「门控 notifier、靠 retained layer 复用」方案无效，撤回。`Ticker.start()` 一旦 active 就每帧 `scheduleFrame()`，回调里哪怕一行不执行，引擎照样 60fps 走完整 `drawFrame → compositeFrame → render(scene)`。所以 GPU 占用**与 notifier 写入频率、绘制内容、柱子数全都无关**，唯一变量是「有没有东西持续请求帧」。这同时解释了此前所有对照：标准滑块 / 整条波形（关 Ticker）都是引擎静止，滚动波形（Ticker active）必然 60fps。

**落地修正**（`lib/widgets/waveform_progress_bar.dart`）：
- 删掉 `Ticker? _ticker` / `_lastFrameTime` / `createTicker` / `_onTick` / `scheduler.dart` import；`dispose` 改 cancel Timer。`TickerProviderStateMixin` 保留（两个 `AnimationController` 的 `vsync: this` 仍需要）。
- 唯一驱动源 `_progressTimer = Timer.periodic(_kScrollingFrameInterval, (_) => _onProgressTimer())`，由 `_updateProgressDriver()` 启停（原 `_updateTickerState` 全量改名，10 处调用点）。周期常量改回 **33ms**（用户实验值 1000 已还原），要调帧率只改这一处。
- `_onProgressTimer()` 的 delta 取固定周期而非测时间戳：Timer 被系统节流时进度短暂落后，靠原有 lerp 0.05 + `didUpdateWidget` 快照 snap 拉回。`didUpdateWidget` 的 seek 同步不经过驱动源，不受影响；拖动 / 惯性 / 长按快进 / 后台 / 最小化的启停门控照旧。

**测试**（`test/widgets/waveform_progress_bar_test.dart` 10 条）：新增 `transientCallbackCount == 0` 直接防止再把 Ticker 加回来；原两条改为验「960ms 内出帧约 29 次」（`greaterThan(15)` 能抓住周期被拖到 1s 的情形）与 seek 同步。

**验证**：两文件 `flutter analyze` → No issues found；`flutter test` 10 条全绿。**仍待用户重新编译实测 GPU**：这次 Ticker 真的不 active 了，若还是十几，说明播放页另有持续 scheduleFrame 的源，需要用 DevTools Performance / `SchedulerBinding` 回调统计定位，别再猜绘制内容。当前改动未提交。
