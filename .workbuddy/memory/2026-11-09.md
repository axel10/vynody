## 实测修复：拖拽中合集浮层冻在原地

用户实测反馈「拖拽时合集停在原地不随鼠标移动」。诊断用 widget test 分别量 `controller.pointer.value` 与 `ZoomReorderPreview` 的 rect：第二次 move 后 pointer 仍是第一次的值（卡在 `Offset(87,289)`），浮层 rect 不动，且伴随 `InheritedElement.notifyClients` 的 "dependent is not our descendant" 断言。

**上面记的「onPanEnd 不送达」只是表象，真因有两层（都是会重复咬人的）：**

1. **起拖后换掉手柄包装层 = 丢掉整条 pointer 链。** 被拖条目 `displaySlotOf` 返回 null → `hidden=true` → `_buildItem` 里 `ZoomReorderHandle(enabled: !hidden)` 把手柄从 `Listener + GestureDetector` 换成纯 `Container`。Flutter 的 pointer 命中路径是 **down 时缓存的 HitTestResult**，换掉包装层后后续 move / up 全发给已卸载的 RenderObject → `onPanUpdate` 停发、合集冻结、拖拽状态卡住。**禁按 hidden / enabled 条件增删手势包装层**（与 `ZoomItemScaffold` 三层常驻同一条不变量）。
2. **pan 与 Scrollable 抢竞技场。** 手柄的 `PanGestureRecognizer` 输给 `CustomScrollView` 的垂直拖拽后 `onPanUpdate` 停发，`onPanCancel` 也未必送达。

**修法（全在 `lib/src/zoom_reorder.dart`）：**

- 手柄改 `StatefulWidget`：`Listener.onPointerDown/Move/Up/Cancel` 直接驱动 `startDrag/updateDrag/endDrag`，位置更新**不经过手势竞技场**；位移超过 `kTouchSlop` 才起拖，避免点一下就弹合集；只跟踪 down 的那根 pointer id。
- 外层 `RawGestureDetector` 注册 `_ZoomReorderHandleRecognizer`（`OneSequenceGestureRecognizer`，`addPointer` 里 `startTrackingPointer` + 立即 `resolve(GestureDisposition.accepted)`），专门抢赢 Scrollable 阻止页面跟着滚；它不处理手势，只占位。
- 手柄层常驻：`showHandle = enabled && (showHandles || controller.isDragging)`，`ZoomReorderHandle` 不再传 `enabled: !hidden`；hidden 内容用 `IgnorePointer` 屏蔽幽灵点击（不影响缓存的 pointer 路径）。
- `ZoomReorderScope` 从 `InheritedNotifier` 改成普通 `InheritedWidget` + `getElementForInheritedWidgetOfExactType`（手柄只需拿 controller 引用调用方法，不需要订阅重建），并移到 `AnimatedBuilder` **外层**保持 element 稳定，消除每帧 notify 触发的 `notifyClients` 断言。

**回归**：新增 `example/test/reorder_pointer_follow_test.dart`（2 项）——断言 pointer 增量、浮层 rect 增量、insertIndex 变化、多选时 preview.count=2、up 后状态复位。验证：包 73 项 + example 5 项全过；包 analyze 仍只既存 1 条 info、example 0 问题。除 `analysis_options.yaml` / `example/pubspec.lock` 外，flutter 工具还会把 `example/macos/Runner.xcodeproj/project.pbxproj` 的 `MACOSX_DEPLOYMENT_TARGET` 从 10.15 改成 12.0，也已还原。

## 实测修复 2：插入位（虚线避让框）整体偏右

用户反馈「合集会动了，但插入位置不在鼠标下面而是偏右边」。诊断量到：demo 网格档 `cols=8 / crossStride=102 / mainStride=172`，内容区 origin `(0,170)`，鼠标 global `(140,300)` → local `(140,130)`，本应是**第 0 行第 1 列**，实际 `insertIndex=7`，虚线框 `(714,170)-(800,318)`，横向偏 574px。

**根因**：`ZoomReorderGeometry.insertIndexFor` 用 `(fy * columns + fx).round()` 把二维位置线性化成一维槽位，`fy` 乘上 `columns` 把「行内垂直偏移」放大成 8 个槽：`fy=130/172=0.756 × 8 = 6.05`，加 `fx=1.37` → 7.42 → 第 7 列（最右）。**这个公式只有在 `columns=1`（列表态）时才碰巧正确**，网格档必错；单测当年也是按这个错误公式写的断言（`(174,0)→2`、`(0,216)→5`），所以没拦住。

**修法**：网格态改成二维分别取整 —— `col = floor(dx/crossStride).clamp(0, columns-1)`、`row = max(0, floor(dy/mainStride))`、`slot = row*columns+col`；列表态保留一维 `round(dy/listStride)`（越过行中心插到下一行）。修后 `(140,130) → insertIndex=1`，虚线框 `(102,170)-(188,318)` 正好罩住鼠标。

**回归**：更新 `test/zoom_reorder_test.dart` 的旧断言（2→1、5→3，并补第 2 行第 2 列 = 8）；新增 `example/test/reorder_insert_position_test.dart`（网格 4 个格子逐个断言 `insertIndex` 与虚线框 rect 罩住指针 + 列表态整行覆盖）。

**测试踩坑**：`_buildPlaceholder` 是 `AnimatedPositioned`（220ms），一次 `pump(300ms)` 里动画还没开始 tick（那一帧才 rebuild 并 `forward`），测出来 rect 仍是旧槽位。必须 `await tester.pump()` 先让 rebuild 把新目标喂进去，再 `await tester.pump(const Duration(milliseconds: 300))` 跑完动画。

验证：包 73 项 + example 7 项全过；包 analyze 仍只既存 1 条 info、example 0 问题。flutter 工具自动改写的 4 个配置/锁文件已全部还原，最终 3 改 + 6 新。

**已提交**：独立仓库 `zoomable_sliver_grid` 的 master 上 `be7d704`（`feat: 新增网格/列表通用的多选拖拽排序引擎与 example 验收 demo`），9 files / +1536 / -3，**未 push**（本地领先 `origin/master` 2 个提交，含既有的 `a5f7808`）。注意 vynody 主仓库用 gitlink(160000) 跟踪该目录，指针仍指向 `a5f7808`，所以主仓库会显示 `M zoomable_sliver_grid`；要同步指针得在主仓库单独提交，本轮未动。
