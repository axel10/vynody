## 远程歌单详情页横屏左侧多空一条 rail

**现象**：横屏下远程歌单详情页内容左边比 rail 多空一整条，本地歌单详情页不会。

**根因**：`remote_playlist_detail_page.dart` 的 `Scaffold.body` 多包了
`Padding(padding: EdgeInsets.only(left: leftPadding))`（`leftPadding =
effectiveSidebarRailWidthProvider(size)`）。但这页**不是全屏路由** —— 它挂在
`folder_page.dart:746` 的嵌套 `Navigator`（`pages:` 式）里，与 `RemoteAlbumDetailPage`
同宿主，渲染位置本身就在 rail 右侧的内容区。再让位一次 = 双重偏移。
本地 `playlist_detail_page.dart` 是同结构写法却是对的，因为它是 `Navigator.push`
到 MainLayout 之上的全屏页，必须自己让位 —— 两者不能照抄。

**改动**：删掉那层 `Padding` 与 `leftPadding` 变量，`Stack` 直接作为 body。顶栏
`Positioned(left/right: 0)` 因此也贴合内容区左缘。`barHeight` 顶部占位保留。

**验证**：`test/pages/remote/` 15 条通过；`flutter analyze lib` 无 error。


## 复核：两份服务端源码里的「歌单排序」能力矩阵

读 `navidrome/`(Go) 与 `jellyfin/`(C#) 本地源码，确认上一节「服务端不支持歌单之间排序」
的判断成立；**易混淆点：歌单内曲目顺序两边都支持，别拿它当歌单之间排序的依据。**

- **歌单之间（列表顺序）**：两边都**没有可写入的自定义顺序字段/接口**。
  Navidrome `server/subsonic/playlists.go:20` `GetPlaylists` 写死 `QueryOptions{Sort:"name"}`，
  Subsonic 协议无 sort 参数；`playlist` 表（`20200130083147_create_schema.go:127`）无排序列，
  `model/playlist.go` 亦无。原生 REST 的 `_sort`/`_order` 只是查询排序不落库。
  Jellyfin 歌单是普通 Item，靠 `GET /Users/{uid}/Items?IncludeItemTypes=Playlist&SortBy=...`
  按属性排（`ItemSortBy` 枚举全是 Name/DateCreated/PlayCount 等属性，无 custom），
  客户端 `jellyfin_client.dart:757-768` 写死 `SortBy=SortName`。
- **歌单内曲目顺序**：都能持久化。真 Jellyfin 三种粒度全有 ——
  `POST /Playlists/{id}/Items/{itemId}/Move/{newIndex}`（`PlaylistsController.cs:408` /
  `PlaylistManager.MoveItemAsync:314`）、`POST .../Items?position=N`、
  `POST /Playlists/{id}` body `Ids` 整体替换（`PlaylistManager.UpdatePlaylist:608` 先清空
  `LinkedChildren` 再按序重建）。Navidrome Subsonic 的 `updatePlaylist.view` **无重排参数**
  （`server/subsonic/playlists.go:95`），只能靠 `createPlaylist.view` 带 `playlistId` +
  有序 `songId` 整体替换（`core/playlists/playlists.go:122` `pls.Tracks = nil` 后重建），
  项目 `SubsonicMediaLibraryClient.reorderPlaylist:195` 正是这么做的；私有原生 REST 才有
  真单曲重排 `PUT /api/playlist/{id}/tracks/{pos}` → `ReorderTrack` → `Reorder()`。
- **兼容性坑**：Navidrome 自己的 Jellyfin 兼容层（`server/jellyfin/`）**没有实现 Move 端点**
  （`README.md:132` 端点表可查，其它路径一律 404），只支持 `POST Playlists/{id}` 带 `Ids`
  整体替换（README:153 明写 "Finamp uses this for reordering"）。所以若把 Navidrome 配成
  Jellyfin 类型，`JellyfinMediaLibraryClient.reorderPlaylist:352` 走的
  `movePlaylistItem` 会 404，须回退到 `Ids` 整体替换。
- 两边整体替换都会重建条目：Navidrome 丢 `playlist_tracks.id`（重复曲目/entry 引用），
  智能歌单与同步歌单被 `TracksEditable()` 拒；真 Jellyfin 重建 `LinkedChildren`。

## 远程歌单列表页：加排序按钮（替换刷新按钮）

**用户拍板**：既然服务端不能持久化「歌单之间顺序」，就只做**展示层按字段排序**；

（与上一节「不做本地记忆顺序 / 不拖拽」不冲突：当时只做展示层排序，不存任何歌单顺序；
「排序字段偏好」是否持久化，见文末同日修订小节。）

**不变量**
- 排序字段枚举 `RemotePlaylistSortField { serverOrder, name, songCount, duration }`
  （定义在 `remote_library_playlists_tab.dart`）。**默认 `serverOrder`** —— 完全沿用服务端

## 同日修订：远程歌单「排序字段偏好」持久化到 settings

**前提复核**（用户质疑「主流 Navidrome 播放器是不是要回写服务端」）：读 `navidrome/ui/` 官方
Web UI 源码确认「歌单列表排序」不回写、服务端也没有可写顺序字段；会回写的是「歌单内曲目顺序」：
- `PlaylistList.jsx:191-194` react-admin `<List sort={name ASC}>` → `ra-data-json-server`
  → `GET /api/playlist?_sort=&_order=`；服务端 `sql_restful.go:54-86` 只做 SQL ORDER BY，不落库。
  `store/createAdminStore.js:58-68` 的 localStorage 只存 theme/library/player/albumView/settings，
  **连排序偏好都不持久化**（刷新回默认 name ASC），也没有 user preference API。
- 真回写的是 `PlaylistSongs.jsx:120-142` 拖拽 → `PUT /api/playlist/{id}/tracks/{pos}`
  (`insert_before`) → `native_api.go:174 reorderItem`。
- `model/playlist.go` 无 order/position 列；`20260104203627_playlist_case_insensitive_name.sql`
  只是修名称大小写不敏感排序。
- 我们的 `serverOrder` 默认值与官方 name ASC 实际等价：Subsonic `GetPlaylists` 写死
  `Sort:"name"`，项目 Jellyfin `getPlaylists()` 写死 `SortBy=SortName`。

**用户拍板**：排序偏好存本地设置即可（不跨设备、不回写）。
**口径**：存的是「按哪个字段 + 升降序」这个视图偏好，**不是**歌单顺序本身；
之前被否决的「本地影子顺序 / 拖拽重排」仍然不做。

**落地**（照 `navidromeArtistSort*` 的纯视图偏好模式，只同步 6 处；不进设置页 UI / 搜索注册表）
- `settings_service.dart`：`_keyRemotePlaylistSortField = 'remote_playlist_sort_field'`
  默认 `'serverOrder'`；`_keyRemotePlaylistSortAscending = 'remote_playlist_sort_ascending'`
  默认 `true`；两个 `SettingProperty` + getter/setter
  `remotePlaylistSortField`(String) / `remotePlaylistSortAscending`(bool)。
  **全局一条、不按 server 区分**（与 album/artist/song 三个 sort 一致）。
- `remote_library_playlists_tab.dart`：唯一解析口 `remotePlaylistSortFieldFromStorage(String?)`
  按 `.name` 匹配枚举，null / 空串 / 未知值一律退回 `serverOrder`（脏值不让页面启动崩）。
- `remote_library_page.dart`：`initState` 从 settings 恢复两个值；
  `_openPlaylistSortDialog()` 回调在 `setState` 后同步写 settings（`result.field.name`）。
  Riverpod 3 的写入只发生在弹窗回调，不在 build / initState 里。

**验证**：`flutter analyze lib` 无 error（只剩既有两个 `_lyrics*Property` unused_field warning）；
`remote_playlist_grid_test.dart` 8 条 + `settings_service_test.dart` 39 条全通过
（新增解析函数往返/容错 2 条，排序默认值与重启持久化并进既有 sort 测试）。
