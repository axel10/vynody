## 本地两个搜索页接入右键菜单 + 跨分节多选

- `LibrarySelectionScope` 新增 `librarySearch` / `folderSearch`（两页都是 push 出来的独立路由，各自挂 `LibrarySelectionBackGuard`）。
- 新增 `lib/utils/search_selection_utils.dart`：选择键统一 `<kind>:<id>`（song/folder/album/artist/playlist），`SearchEntry` 描述一条命中，`expandSearchEntries(entries, loadFolderSongs)` 把集合展开成去重歌曲（folder 的歌曲由调用方注入 `scanner.getSongsForFolder`，因为搜索结果的 `MusicFolder` 是空壳、`allSongs` 恒空）。
- 页面结构：build 时按视觉顺序拼扁平 `entries`（媒体库 艺术家→歌单→专辑→歌曲；目录 当前目录文件夹→当前目录歌曲→全局文件夹→全局歌曲），`handleItemTap(index: 全局下标, allKeys: entryKeys)` 负责 Shift 跨段连选 / Ctrl 点选 / 多选态点选切换；长按一律进多选；右键菜单全部传 `onMultiSelect`（选态下传 null）。
- 选择集变化时异步展开 `_selectedSongs` 缓存供面板与多选态右键复用（签名不符则丢弃，异常吞掉保留上次结果）。
- 面板 `LibrarySelectionPanel(selectedSongs: 展开结果, title: selectedItemsCount)`，不传 onDelete。
- 改搜索词/清空时 `cancelSelection()`，避免选择集与页面条目脱节。
- 测试：`test/utils/search_selection_utils_test.dart` 8 例；两个页面测试各加长按进多选/混选/跨段全选/改词退出。20 例全过。
- 已知既有失败：`test/pages/library_multiselect_test.dart` 两例仍找 `Icons.close`，而提交 e2918e00 已把面板关闭按钮改成 `Icons.close_rounded`（与本次改动无关）。

## 远程媒体库搜索页跨栏目多选

把远程搜索页选择模型改成与本地搜索页同构：整页一套 `Set<String>`，键 `<类型>:<id>`，
艺术家 / 专辑 / 歌曲可混选，Shift 连选按视觉顺序（艺术家 → 专辑 → 歌曲）跨段成立，
集合类条目按「它包含的全部歌曲」参与批量动作。

- 选择集只有一套：进搜索页多选时 `_clearTypedSelections()` 清掉另外四套集合。其余 5 个
  tab 仍是「按类型各存一份 + 互斥」，没动。
- `RemoteLibrarySearchView.entryKeysFor()` 是页面键序列唯一来源：视图内算各段 base 索引、
  页面算全选都用这一份，避免键顺序与行顺序各推一遍。
- 底层两条独占链改累加：`fetchSelectedBatches`（原 `if/else if`）、
  `handleBatchAddToCloudFavorites`（原分支内 `return`）。
- 云端收藏传「直接勾中的曲目」（`directSongs`）而不是集合展开结果，否则勾一张专辑会把
  整张专辑的曲目再逐首收藏一遍。
- 多选态右键对齐本地：歌曲行走 `showRemoteSongContextMenu(resolveSelectionBatches:)`
  （新钩子，拉曲目套 `runWithRemoteTrackLoadProgress`，下载走 `RemoteDownloadRequest.grouped`
  保留落盘层级）；专辑 / 艺术家菜单照常弹，只是 `onMultiSelect: null`。
- 顺带修：`test/pages/remote/remote_library_search_tab_test.dart` 改造前就已陈旧跑红
  （按 `ListView` 分段断言，实现早已是 `CustomScrollView` + `SliverGrid`），已按新 API 重写。
  `flutter analyze lib` 无 error，`flutter test test/pages/remote` 58 例全过。

计划与结果：`docs/远程搜索页跨栏目多选-现状与改造计划.md`。
