## 修复：Android 设置里关闭 USB 独占后无声（进度条正常走）

**现象**：设置里点开关关 USB 独占 → 无声但进度条走；直接拔 USB DAC → 外放正常。
后者证明系统音频路由/`nativeClearDevice()` 恢复内核驱动都正常，问题只在「设置关闭」比「拔线」多走的那一步 `reloadActivePlayersForAudioRouteChange()`。

**根因**：`SwitchableUsbAudioSink`（audio_core Android）是 `ForwardingAudioSink` wrapper。
USB 独占期间 `configure()` 走 USB 分支直接 return，从不调 `super.configure()`，所以 delegate `DefaultAudioSink` 一直停留在独占会话之前的陈旧状态。
切回普通输出时：
- `reset()` 旧代码在 `usingUsbForCurrentConfig` 分支里直接 `return`，**没有转发 `super.reset()`**；
- `configure()` 切回分支同样只置 flag + release ownership，也没 `super.reset()`。
结果 delegate 被重新 configure/play 却从未 reset，AudioTrack 收不到 PCM → 无声；`getCurrentPositionUs()` 退回 media clock → 进度条照走。

**修复**（`audio_core/.../SwitchableUsbAudioSink.kt`）：
- `reset()`：USB 分支不再 return，末尾无条件 `super.reset()`；
- `configure()` 的 `if (usingUsbForCurrentConfig)` 切回分支：先 `super.reset()` 再 `super.configure()`（reset 幂等，两条路径都安全）；
- 两处加 `NativeLog.d("UsbExclusive", ...)` 便于真机确认。
两条切回路径（ExoPlayer stop→reset，或直接 configure）现在都会先 reset delegate。

**验证**：上述 Kotlin 改动真机验证 **无效**（ redesploy 后仍无声）。日志证明 sink/ExoPlayer 层正常：关闭后 AudioTrack 重建、音量 1.0、maxAmplitude 26115（在写 PCM）、`onAudioDeviceUpdate` 仍为 `AUDIO_DEVICE_OUT_USB_HEADSET`。这个 Kotlin 改动本身正确性成立（修正 wrapper 吞掉 delegate.reset 的契约违反），作为防御性保留，**但不是无声根因**。

## 真正根因（真机日志定位）：关闭独占后内核 snd-usb-audio 没重新接管 DAC

日志证据（Redmi / Android 17 / CX31993 UAC2）：
- `Registered exclusive USB DAC` → `Configured stream` → 关闭 `Released exclusive USB DAC`（Rust）；
- 关闭后 PCM 正常送到 USB AudioTrack 但设备不出声；
- **拔 DAC** 触发物理 disconnect → 内核重新 probe 绑定驱动 → 外放有声。

机制：`claim_interface_force()`（engine.rs）为抢占接口，必要时用 raw `USBDEVFS_DISCONNECT` ioctl 强制解绑内核驱动（stale usbfs / auto-detach 已消耗 libusb detach 路径时）。恢复路径分两支：
- `restore_kernel_driver()`（强杀后启动恢复）：先 force-disconnect 残留 usbfs，再用 **`force_connect_usbfs_driver()` / USBDEVFS_CONNECT** 真正重绑 → 有效；
- `release_interfaces_and_restore_kernel()`（**正常关闭 clear_device 走这条**）：只调 `handle.attach_kernel_driver(iface)`，且 `let _ =` 吞掉错误。libusb 的 attach 只对「自己 detach 过的接口」有效，对 ioctl 强制 DISCONNECT 的接口是 no-op → snd-usb-audio 仍 unbound → Android 路由到 USB 但没驱动 → 无声。

**修复**（`audio_core/rust/src/usb_audio/engine.rs`）：
- `release_interfaces_and_restore_kernel` 增加 `fd: RawFd` 参数，`attach_kernel_driver` 之后追加 `force_connect_usbfs_driver(fd, iface)` 兜底（已绑定时 no-op），并加 info 日志；
- 三处调用点传入 fd（正常关闭 `clear_device` / register 覆盖旧设备 / register 失败回滚），fd 来自 `RegisteredDevice._owned_fd.raw()`（dup fd，Java `nativeClearDevice()` 先于 `activeConnection.close()`，调用时有效）。

**验证**：`cargo check --lib` 与 `cargo check --lib --target aarch64-linux-android` 均通过（仅既有 warning）。**未真机验证**——需重新编译 native 库并装机。真机确认看 tag `audio_core::usb_audio::engine` 是否打印 `release: USBDEVFS_CONNECT iface=... -> Ok(...)`。

**关键约定**：USB 独占关闭/恢复内核驱动，唯一有效路径是 `USBDEVFS_CONNECT`（`force_connect_usbfs_driver`）；libusb `attach_kernel_driver()` 不可靠（只对自身 detach 有效）。正常关闭 `clear_device()` 与强杀恢复 `restore_kernel_driver()` 必须同源。

**环境**：本机 adb 连真机 `adb-945cc1e-zRlgWE`（Redmi 25053RT47C / onyx / Android 17）。NativeLog 同时写 logcat（tag 如 `UsbExclusive`/`AudioCore`）和 `<filesDir>/audio_core_logs/android.log`；Dart 侧日志在 `vynody.log`。Rust log::info 只进 logcat，tag `audio_core::usb_audio::engine`。查 USB 无声用 `adb logcat -d -v threadtime | rg 'UsbAudio|UsbExclusive|onAudioDeviceUpdate|AudioTrack.*setVolume'`。
